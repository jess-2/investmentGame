## 현재 적용 규칙 (2026-11-10)

이 절이 아래의 2026-11-09 주차별 거래 설계보다 우선한다. 아래 내용은 변경 이력으로 보존한다.

- 진행: **정보 탐색 → A→B→C→D 각 7초 매수 × 2회 → 진입·청산 구간 결정 → 시장 공개·기존 시장 이벤트 결과 → 정산**.
- 주차별 4회 매수와 각 3초 시뮬레이션, 중간 주가 공개는 사용하지 않는다. 매수 및 구간 결정 중에는 전체 시장이 공개되지 않는다.
- A/B/C/D는 해당 턴 자리 순서다. 기존 턴별 자리 순환과 선점 투자자 증강은 유지한다. 순서는 **A→B→C→D→A→B→C→D**이며 역순으로 돌지 않는다. 각 플레이어는 턴당 두 번의 매수 창을 갖는다.
- **매수 창 하나는 7초, 새 매수량 합계는 최대 15주**다. 기업 카드의 회색 칸은 남은 물량이고, 수량을 움직이면 내 색으로 채워진다. 슬라이더를 놓으면 즉시 서버에 주문하며 별도 `거래 적용` 버튼은 없다. 키보드 수량 조정도 자동 주문한다. 매수로 시간이 연장되거나 차례가 끝나지 않으며, `매수 완료 · 다음 차례` 또는 시간 만료 시 다음 사람으로 넘어간다.
- 예: A의 첫 차례에 AI 10주 + SPACE 5주, 두 번째 차례에 FOOD 10주 + AUTO 5주를 매수하면 총 30주다. 기업별 개인 한도와 시장 잔여 공급량은 각각 검사한다.
- 주문 실패·동일 요청 재전송은 매수 한도를 소모하지 않는다. 같은 차례에서 주식을 팔아도 이미 사용한 15주 한도가 복구되지 않는다. 첫 차례에서 남긴 매수 한도는 두 번째 차례에 더해지지 않는다.
- 여러 기업 동시 주문은 모든 플레이어의 기본 규칙이므로 기존 `FLEXIBLE` 증강은 새 후보에서 제외한다. 기존 저장값의 식별자와 설명은 호환을 위해 유지한다.
- BANK 외 기업은 각 20주, 개인별 기업 한도는 기본 10주(집중 투자자 대상 기업 12주), 개인 총량은 30주다.
- **새 턴이 시작되면 모든 플레이어의 보유 주식·확보 물량·예약을 초기화한다.** 플레이어마다 30칸 전부 BANK로 시작하고, BANK 외 기업은 각각 20주가 다시 매수 가능해진다. 완료된 턴의 결과 화면에서는 당시 보유량을 유지하다 다음 턴 진입 시 초기화한다.
- 정산한 자산·수익·지난 턴 거래 이력·선택한 증강은 유지한다. 주식 수량이 자동 이월되지는 않는다. 연속 투자형 증강은 같은 기업을 **매 턴 다시 매수**해야 이어지며, 한 턴 건너뛰면 연속 기록이 끊긴다.
- 다른 기업에 투자하지 않은 수량은 **전부 BANK 자동 예금**이다. 직접 BANK를 주문하지 않는다. BANK의 총 수용량은 **120주**이며 개인당 30주까지 예금한다. 진입 전과 청산 후에도 해당 슬롯에 BANK 수익률을 적용한다.

## 0. 게임 개요와 변경 기준

4명의 플레이어가 6개 기업의 한정된 주식을 확보하고, 30칸 포트폴리오와 증강을 활용해 최종 자산을 겨룬다. 기존의 코인 기반 숨겨진 정보 구매와 진입·청산 구간 예약을 유지한다.

**한 턴은 정보 탐색 60초 + 주가 변동 단계 172초 = 최대 232초**다. 주가 변동 단계는 `주차별 거래 40초 → 시뮬레이션 3초`를 4번 반복한다. **시뮬레이션 중에는 확정된 예약 거래만 자동 실행**한다.

이 문서는 구현 목표다. 하단의 과거 구현·검증 기록은 이전 버전의 이력이며, 최신 설계가 구현·검증되었다는 의미가 아니다.

## 1. 한 턴의 시간과 진행

### 1.1. 최대 시간을 사용한 경우의 시간표

| 턴 경과 시간 | 단계 | 거래 순서 / 처리 |
|---|---|---|
| 0~60초 | 정보 탐색 | 코인으로 정보 구매, 진입·청산 구간 예약 초안 설정 |
| 60~100초 | 1주차 거래 | A → B → C → D, 개인당 10초 |
| 100~103초 | 1주차 시뮬레이션 | 1~7일 공개, 확정 예약 실행 |
| 103~143초 | 2주차 거래 | B → C → D → A, 개인당 10초 |
| 143~146초 | 2주차 시뮬레이션 | 8~15일 공개, 확정 예약 실행 |
| 146~186초 | 3주차 거래 | C → D → A → B, 개인당 10초 |
| 186~189초 | 3주차 시뮬레이션 | 16~22일 공개, 확정 예약 실행 |
| 189~229초 | 4주차 거래 | D → A → B → C, 개인당 10초 |
| 229~232초 | 4주차 시뮬레이션 | 23~30일 공개, 확정 예약 실행·턴 결과 계산 |

주차는 게임 내 편의 명칭이다. 달력의 정확한 7일 단위 대신 30일을 네 구간으로 모두 공개한다. 각 시뮬레이션은 일수와 관계없이 3초이며, 서버는 해당 구간의 날짜를 순서대로 처리한다.

```text
[지정 턴에만 증강 선택: 기본 턴 시간 밖]
                    ↓
[정보 탐색 60초: 정보 구매 + 예약 초안]
                    ↓
[1주 거래 40초] → [1~7일 시뮬레이션 3초]
                    ↓
[2주 거래 40초] → [8~15일 시뮬레이션 3초]
                    ↓
[3주 거래 40초] → [16~22일 시뮬레이션 3초]
                    ↓
[4주 거래 40초] → [23~30일 시뮬레이션 3초]
                    ↓
[턴 결과·순위 표시 → 다음 턴]
```

결과는 마지막 시뮬레이션 종료 시 계산하여 화면에 표시한다. 결과 확인 시간(최대 5초)과 지정 턴의 증강 선택 시간은 기본 턴과 별도로 계산한다.

### 1.2. 자리와 순서 순환

A·B·C·D는 고정 플레이어 이름이 아니라 **해당 턴의 자리**다. 게임 시작 시 플레이어를 자리에 배정하고, 매 턴 자리를 한 칸씩 순환한다.

| 턴 | A | B | C | D |
|---|---|---|---|---|
| 1턴 예시 | P1 | P2 | P3 | P4 |
| 2턴 예시 | P2 | P3 | P4 | P1 |
| 3턴 예시 | P3 | P4 | P1 | P2 |
| 4턴 예시 | P4 | P1 | P2 | P3 |

각 플레이어는 매 턴 네 차례를 받으며, 네 주 동안 각 순번을 한 번씩 경험한다. 30칸이 찰 때까지 추가 순환하지 않는다. 공용 정보 선택 후 개인 탐색은 동시에 진행한다. 네 명이 완료하면 즉시 거래를 시작한다. 개인 거래 차례는 최대 10초이며 주문 확정 또는 거래 없이 완료를 누르면 즉시 다음 차례로 넘어간다. BOT도 정보 구매나 주문을 마치면 같은 방식으로 완료한다.

## 2. 정보 탐색·주차별 거래·시뮬레이션의 권한

| 행동 | 정보 탐색 60초 | 주차별 본인 차례 10초 | 시뮬레이션 3초 |
|---|---|---|---|
| 코인으로 숨겨진 정보 구매 | 가능 | 불가 | 불가 |
| 예약 초안 작성·로컬 미리보기 | 가능 | 가능 | 불가 |
| 직접 매수·매도 | 불가 | 가능 | 불가 |
| 예약 생성·수정·취소 확정 | 불가 | 가능 | 불가 |
| 확정 예약의 자동 실행 | 없음 | 없음 | 해당 날짜에 실행 |
| 주가 순차 공개 | 없음 | 직전 공개 시점 유지 | 진행 |

다른 사람의 거래 차례에는 자신의 다음 주문 초안을 준비할 수 있지만 서버 확정은 할 수 없다. 시뮬레이션 중에는 주문 편집 UI를 잠그고 서버도 직접 거래·예약 변경 요청을 거부한다.

정보 탐색의 사전 세팅은 **예약 초안**이다. 정보 탐색 중에는 주식이나 슬롯을 선점하지 않는다. 주차별 자기 차례에 확정해야 실제 예약이 된다. 따라서 미리 예약했다는 이유로 순차 매수 규칙을 우회할 수 없다.

### 2.1. 주차별 자기 차례

1. 공개된 주가, 시장 잔여량, 본인 보유량·예약량·남은 슬롯을 확인한다.
2. 직접 매수·매도 및 미래 진입·청산 예약의 초안을 검토한다.
3. 한 번의 확정 요청으로 주문을 제출한다. 기본은 한 기업, 유연한 투자자는 두 기업까지다.
4. 서버가 물량·한도·날짜·자산을 모두 검증한 뒤 원자적으로 반영한다.
5. 성공한 확정은 해당 차례의 주문권을 소모한다. 패스도 가능하다. 실패 시 차례 마감 전까지 수정·재시도할 수 있다.

선택한 기업에 대한 직접 거래와 예약 조정을 같은 요청에 담을 수 있다. 요청 전체가 성공하거나 전체가 실패한다. 시간 초과 시 이미 확정된 보유·예약을 유지하며 초안은 자동 제출하지 않는다.

### 2.2. 예약 매수·매도와 공용 물량

예약 매수가 드래프트를 우회하거나 미래에 품절되는 문제를 막기 위해 **예약 매수는 본인 차례에 확정할 때 물량과 슬롯을 확보**한다.

- 기업별 `실제 보유량 + 미실행 매수 예약량`의 전체 합계는 20주 이하다.
- 개인의 같은 합계는 기업당 기본 10주, 집중 투자자 대상 기업은 12주 이하다.
- 실제 보유와 미실행 매수 예약은 합쳐 30칸 이하다. 예약 진입 전에는 해당 슬롯을 BANK에 예치하되 다른 주문에 중복 사용하지 못한다.
- 예약 초안은 물량·슬롯을 점유하지 않는다. 확정된 예약 매수를 취소하면 확보 물량·슬롯을 반환한다.
- 예약 매수가 실행되면 확보량을 실제 보유량으로 옮긴다. 이때 공용 물량을 두 번 차감하지 않는다.
- 직접 매도는 체결 즉시, 예약 매도는 실제 청산 시점에 공용 물량과 슬롯을 반환한다. 청산 예약만으로 미리 반환하지 않는다.
- 시뮬레이션 중 반환된 물량은 다음 주차 거래부터 새로 확보할 수 있다. 마지막 주에 반환되면 다음 턴부터 가능하다.
- 부분 체결은 사용하지 않는다. 예약량까지 포함해 요청 전체를 검증하며, 보유·확보하지 않은 주식의 매도와 중복 매도 예약은 금지한다.

따라서 **주식을 새로 확보하는 기회는 주차별 본인 차례뿐**이다. 시뮬레이션의 예약 진입은 본인 차례에 이미 확보한 물량의 투자 시작이다.

### 2.3. 체결 시점과 예약 잠금

- 주차별 직접 거래는 직전까지 공개된 종가로 체결한다. 1주차 전에는 0일 기준가를 사용한다.
- 예약 진입은 지정일 시가, 예약 청산은 지정일 종가로 처리한다. 날짜별 시가·종가와 수익률의 정의는 시장 데이터와 일치시킨다.
- 거래 단계에서는 아직 진행하지 않은 날짜의 예약만 생성·수정·취소할 수 있다. 이미 실행된 거래나 공개된 과거 날짜는 바꿀 수 없다.
- 해당 주차의 네 번째 차례가 끝나면 서버가 예약 상태를 잠근다. 이어지는 3초 동안 확정 예약만 날짜 순서대로 실행한다.
- 같은 날 진입·청산은 시가 진입 후 종가 청산 순서다. 다른 슬롯의 청산 자금·물량에 의존한 미확보 예약은 허용하지 않는다.
- 이후 주차의 예약도 시뮬레이션 동안 변경할 수 없으며, 다음 본인 거래 차례에 미래 날짜에 한해 다시 조정할 수 있다.
- 이미 보유한 주식은 예약 매도가 없으면 계속 보유한다. 매주나 턴 말에 강제로 매도하지 않는다.

서버 수신 시각이 차례 마감 이전인 요청만 처리한다. 마감 시각과 같거나 이후인 변경 요청은 거부한다. 중복 요청으로 거래·보상·예약이 두 번 적용되지 않게 한다.

## 3. 기업별 20주와 플레이어별 30칸

### 3.1. 기본 제한

BANK는 30칸 중 실제로 다른 기업에 투자하지 않은 모든 칸을 자동 운용한다. 예약 진입 전과 청산 후에도 BANK 수익률을 적용한다. 네 명 모두 30칸을 예금할 수 있도록 BANK에는 공급·개인 한도가 없고 직접 주문하지 않는다. 일반 기업 카드는 플레이어 이름·고유색 사각형·수량(예: P1 🟦 ×10), 잔여량은 회색 사각형과 실제 수량으로 표시한다. BANK 카드는 예금 수량을 표시한다. BANK 시세는 기존 BANK 패턴을 축소하여 기준가 대비 ±2% 이내로 움직인다.

| 항목 | 규칙 |
|---|---|
| 기업 | AI / BIO / SPACE / AUTO / FOOD / BANK |
| 기업별 총 공급 | BANK 외 각 20주, 보유량과 확정 매수 예약량을 합쳐 제한 |
| 개인별 기업 한도 | 기본 10주, 집중 투자자 대상 기업만 12주 |
| 개인 포트폴리오 | 30칸, 1주 = 1칸 |
| 빈칸 | BANK 자동 예금. BANK 그래프의 실제 수익률 적용 |
| 보유 기업 수 | 고정 2개 기업 제한 없음 |
| 이월 | 보유 주식은 다음 턴으로 이월. 해당 턴 날짜로 지정한 미실행 예약은 턴 말 만료 |

확정 예약에 묶인 BANK 예금과 새 주문에 쓸 수 있는 BANK 예금을 UI에서 구분한다. 주가 상승으로 슬롯 평가액이 늘어도 점유 칸 수는 늘어나지 않는다.

### 3.2. 자산 비중과 실제 구간 손익

각 턴 시작의 투자 가능 자산을 30칸에 균등 배분한다. 슬롯별 가격 변화를 소수 정밀도로 기록한 뒤 기업별 손익을 최종 자산 단위로 반올림한다. 턴 안에서는 각 슬롯의 현금·진입가·현재 평가액·실현 손익을 기록하고, 거래할 때마다 전체 자산을 다시 30등분하지 않는다.

- 진입 전과 청산 후의 슬롯에는 BANK의 일별 수익률을 적용한다.
- 주식을 보유하는 동안 실제 진입가 대비 가격 변동을 반영한다.
- 청산하면 해당 슬롯 전액을 BANK에 자동 예치한다. 나중에 재투자하면 그 슬롯에 남은 금액을 사용한다.
- 동일 기업이라도 진입일이 다르면 매입 기준을 별도로 기록한다. 청산 대상 슬롯은 주문에서 지정한다.
- 계속 보유하는 주식은 턴 말 종가로 평가한다. 다음 턴에는 그 시점까지의 손익을 자산에 반영한 뒤 새 턴 기준으로 슬롯 배분금·가격 기준을 갱신한다. 이미 반영한 가격 변동을 다시 더하지 않는다.

한 슬롯의 구간 수익률은 `청산 가격 / 진입 가격 - 1`이다. 슬롯 안에서 여러 번 재투자하면 각 구간의 자산 변화를 순서대로 반영한다. 전체 자산은 **BANK 예금 평가액 + 다른 기업의 보유 슬롯 평가액 + 증강 보상**으로 집계한다.

예를 들어 AI 10칸을 보유 기간 동안 100% 상승한 가격에 청산하고 다른 20칸의 변동이 없다면, 전체 수익률은 `10/30 × 100% ≈ 33.33%`다. 다만 중도 진입·청산한 슬롯에 0일→30일 수익률을 그대로 적용해서는 안 된다.

`1주 = 1칸`은 게임 내 투자 단위다. 기업의 원화 주가로 동일 수량을 사는 현실 주식 모델과는 구분한다. 서로 다른 플레이어의 슬롯 투자금이 달라도 기업 공급 제한에는 동일한 1주로 센다. 한 칸에 여러 주식을 넣는 복합 칸 모델은 사용하지 않는다.

### 3.3. 매수 UI

거래 중에는 각 기업 카드에 일봉 그래프를 표시한다. 공개된 날짜와 본인이 열람한 날짜만 표시한다.

- 개인 한도 대비 목표 비율: 기본 10주일 때 10% = 1주, 100% = 10주.
- 전체 공급 대비 비율: 10/20 = 50%.
- 턴 시작 배분 기준 자산 비중: 10/30 ≈ 33.33%. 턴 도중 실제 평가액 비중과는 별도로 표시한다.
- 기업별 실제 보유·예약 확보·남은 공급을 구분한다. 전원의 정확한 물량은 공개하되 미래 예약 날짜·개인 정보는 공개하지 않는다.
- 정보 탐색 때 만든 초안을 다음 본인 차례에 빠르게 확정할 수 있게 한다. 시뮬레이션 중에는 입력을 잠그고 공개 주가와 예약 실행 결과를 보여준다.

## 4. 증강 12종과 적용 시점

증강은 선택한 플레이어에게만 적용한다. 공통 주가를 바꾸는 효과는 시장 이벤트로 분리한다. 증강마다 전용 진행 시간을 추가하지 않고 기존 정보·거래·정산 단계에 연결한다.

**기존 6턴 구성과 1·3·5턴 증강 선택은 유지한다.** 지정 턴의 정보 탐색 **전**에 20초 동안 미보유 후보 3개 중 하나를 선택한다. 이 시간은 기본 턴 232초 바깥이다. 중복 선택은 없고 미선택 시 첫 후보를 자동 선택한다. 집중 투자자의 대상 기업도 이때 지정한다.

| 증강 | 효과와 초기 수치 | 적용 시점 |
|---|---|---|

### 4.1. 보너스와 연속 보유의 중복 방지

- 연속 보유는 기업의 실제 보유량이 양수인 상태가 유지되는지를 기준으로 한다. 전량 매도하면 즉시 초기화하고 예약 확보만으로는 연속 보유를 인정하지 않는다.
- 첫 진입한 턴을 1턴으로 세고, 다음 턴까지 실제 보유가 끊기지 않으면 누적한다. 턴 종료 시 보유가 없으면 연속 보유 보너스를 받지 않는다.
- 장기·SPACE 보너스는 이번 턴 중 계속 유지한 물량과 턴 경계에서 이어진 적격 물량에만 적용한다. 이번 턴에 추가 매수한 물량은 기존 물량의 보유 기간을 물려받지 않는다.
- 부분 매도는 가장 최근에 매수한 슬롯부터 처리하는 것을 기본값으로 UI에 제시하되, 최종 청산 대상 슬롯은 주문에 명시한다.
- 보너스는 시뮬레이션이 4번이라는 이유로 네 번 지급하지 않는다. 서로 다른 증강의 적격 보너스는 합산한다.
- 정산 순서: 실제 보유 구간 가격 손익 → 해당 구간의 위험 분산 손실 완화 → 연속 보유 보너스 → 현금 보너스 → 전체 자산 하한 적용.
- 차트에는 시장 원본 가격을 표시하고 증강에 의한 개인 손익은 별도 표시한다.

수치와 조건은 초기 밸런스 값이며 플레이테스트에 따라 변경한다. 투자 성향은 증강 조합의 권장 방향이며 기업·증강 선택을 강제 제한하지 않는다.

## 5. 구현 반영 항목과 검증 기준

### 5.1. 변경할 시스템

- 진행: INFO 60초, 4주 거래/시뮬레이션 상태, 주차·자리·개인 차례·서버 마감 관리. 기본 턴 최대 232초.
- 원장: 실제 보유와 예약 확보를 구분하고 기업 20주·개인 10/12주·총 30칸을 동시에 검증.
- 예약: 정보 탐색 초안, 본인 차례 확정, 미래 날짜 수정, 시뮬레이션 잠금, 일자별 자동 실행과 만료 처리.
- 정산: 기존 전체 기간 일괄 수익률을 슬롯별 진입·청산·평가손익과 이력으로 교체.
- 증강: 정보 탐색 전 선택, 주차별 순서 개입, 실제 보유 기간·현금 기록을 사용하는 보너스 처리.
- UI/BOT: 개인 차례 10초에 맞춘 초안 확정·패스, 시뮬레이션 입력 잠금, 주차별 공개와 예약 결과 표시. BOT도 같은 명령·한도를 사용.
- 기존 기능: 코인 정보 구매·날짜별 구간 계획·패턴 시장·네트워크·기록 조회를 재사용. 기존 고유능력·자리 입찰·상점·아이템을 다시 활성화하는 것은 이번 변경 범위에 포함하지 않음.

## 6. 과거 구현·검증 기록 — 최신 설계 적용 전

다음은 문서 갱신 전 기록이다. **이번 232초·주차별 예약 거래 설계의 통과 결과로 재사용하지 않는다.**

기존 기록에는 `feat/stock_system`에 일반 게임을 적용하고 이전 패턴·구간 거래 버전을 `feat/stock_pattern`의 `811ea9a`로 보존했다고 적혀 있다. 당시 규칙은 6턴, 8회 드래프트, INFO 90초, 전체 기간 정산이었다.

당시 구현 위치:

- `StockSystemContracts.cs`: 수량·증강·포트폴리오 DTO.
- `StockSystemMarket.cs`: 주식 원장·수량 검증·이월·증강·30칸 정산·분석 정보.
- `StockSystemFlow.cs`: 6턴·증강 타이머·8회 순서·자동 패스.
- `StockSystemPage.cs`: 소유 현황·슬라이더·포트폴리오·증강 선택.
- `StockSystemValidation.cs`: 수량·품절·재전송·정산·6턴·증강 서버 검증.

기존 문서의 검증 기록은 .NET 65개, Unity 166개 통과 및 방장/참가자/BOT TCP·UI 확인이다. 기록 경로는 `Logs/AValidation-results.json`, `Logs/StockSystem-final-results.xml`, `Logs/StockSystem-final-Unity.log`, 격리 프로젝트 `.validation/TradingUX`의 `Logs/PlanningScreens/stock-system-*.png`다. 이 문서 수정에서 해당 결과를 재실행하거나 재확인하지 않았다. 실제 외부망·물리 PC 4대 검증과 승률 밸런싱도 별도 작업이다.
