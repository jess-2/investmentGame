# 투자 게임: 차트 패턴 및 정보 탐색 설계

현재 일반 게임의 6턴·증강·주식 경쟁 규칙은 [주식 게임 시스템 기획서](stock_game_system_design.md)를 따른다. 이 문서는 `feat/stock_pattern` 버전의 차트 탐색 설계 기록이다.

2026-11-09: 현재 조작의 예약 자동 적용·구간 제한 해제·시장 공개 표시는 [조작 개정](DAILY_INFO_MOUSE_TRADING.md)을 따른다. 투자자 3유형·기업 상태·공통 뉴스 구상은 [별도 구현 계획](INVESTOR_TYPES_MARKET_EVENTS_PLAN.md)으로 관리하며 아직 게임에 적용하지 않았다.

패턴 확인 도구와 차트 표시 개정: **BlackWhale → 패턴 실험실**, 현재 열람값 기준 자동 Y축, 상·하한 퍼센트 미표시를 반영했다. [실험실 사용법](PATTERN_LAB.md)을 따른다. 아래의 종목 한도는 생성 제약이며 현재 화면의 Y축 범위가 아니다.

**현재 적용은 v4다.** 하루당 1코인·초반/후반 15/25코인, 마우스 범위 선택·예약·드래그 편집·키보드 삭제, 진입일 시가/청산일 종가를 사용한다. 상세는 [하루 단위 정보·마우스 거래 개정](DAILY_INFO_MOUSE_TRADING.md)을 따른다. 아래는 패턴 도입 당시 1차 설계 기록이며, 고정 5일 개인 구매·3/5코인·종가 진입 설명보다 이 개정이 우선한다. 공용 공개 5일·4명·10초와 패턴 생성은 유지한다.

개정일: 2026-11-08. **1차 구현을 게임 코드에 반영했다.** 구현 범위와 검증은 [STOCK_PATTERN_IMPLEMENTATION.md](STOCK_PATTERN_IMPLEMENTATION.md)에 기록한다. 아래의 후속 실험·OHLC·뉴스·거래량은 계속 설계안이다.

## 1. 이번 개정의 기준

### 요청에 따라 변경할 규칙
- 기업마다 정보 2개씩, 총 12개를 무작위 기본 공개하는 방식을 폐기한다.
- **4명의 플레이어가 돌아가며 정보 1개씩을 해제하고, 총 4개의 정보를 전원에게 공개한다.** 기업별 4개가 아니라 6개 기업 전체에서 총 4개다.
- 개인이 코인으로 산 정보는 기존처럼 구매자에게만 보인다. 공용 공개와 개인 구매를 구분한다.

### 구체화를 위한 권장안
- 고정된 5일 묶음 대신 **원하는 위치의 연속 5일을 선택**한다. 예: 3~7일, 9~13일, 26~30일.
- 공개 선택에도 같은 5일 창을 사용한다. 공개 선택을 마친 뒤 개인 탐색을 시작한다.
- 패턴은 숨겨진 차트를 추론하는 단서로 사용한다. 패턴 이름 자체를 정답으로 공개하지 않는다.
- 비용·시간·패턴 비중 등 아래 초기 수치는 플레이 테스트용 제안이다.

## 2. 현재 구현과 설계의 접점

현재 프로젝트를 확인한 결과:
- 기업은 AI·SPACE·FOOD·AUTO·BIO·BANK 6개, 참가자는 4명, 일반 게임은 10턴이다.
- 차트는 **0일차 기준값 0%와 1~30일차의 기준 대비 변화율**이다. 기존 정보 묶음은 정확히 `1~5, 6~10, …, 26~30일`이다. `0~5일`은 6개 날짜이므로 정보 단위로 쓰지 않는다.
- 투자자는 날짜를 골라 진입·청산한다. 보유 기간은 5~10일이고, 기업마다 최대 2개 구간을 사용한다.
- 정산은 `청산일의 기준 대비 변화율 - 진입일의 기준 대비 변화율`을 합산한다. 실제 가격 비율이나 일별 복리 수익률 공식과 다르다.
- 서버는 턴 시작에 전체 시장을 생성하고 고정한다. 정보 구매나 재접속으로 시장이 바뀌지 않는다.
- 현재 데이터는 일별 값 배열이다. OHLC 캔들 데이터는 별도 확장이 필요하다.

핵심 재미는 **숨겨진 30일 차트에서 유리한 투자 구간을 찾아내는 것**이다. 원문의 '과거 패턴으로 이후 미래를 예측한다'는 설명은 현재 정산 방식과 구분한다. 이번 제안은 현재 투자·정산 규칙을 전제로 한다. 별도 미래 가격 예측 모드는 후속 과제다.

참조 코드:
- `Assets/Scripts/Rules/Market/RandomMarketGenerator.cs`: 턴별 시장 생성·캐시, 기업별 변동 한계.
- `Assets/Scripts/Rules/Market/Settlement.cs`: 날짜별 변화율 차이로 정산.
- `Assets/Scripts/Rules/Market/OrderValidator.cs`: 날짜·보유 기간·구간 중복 검증.
- `Assets/Scripts/Rules/Information/InformationContracts.cs`: 기존 5일 묶음·가격 계약.
- `Assets/Scripts/UI/Presentation/GraphSeriesBuilder.cs`: 열람 날짜만 표시하며 숨은 날짜를 건너 선을 잇지 않음.

## 3. 핵심 플레이 경험

매 턴 다음 세 가지 판단을 만든다.
1. **공개 선택:** 모두에게 보여줘도 괜찮은 정보는 무엇인가? 관심 기업을 드러낼 것인가?
2. **개인 탐색:** 코인을 여러 기업에 분산할 것인가, 한 기업의 빈틈을 연결할 것인가?
3. **투자 결정:** 확인한 구간에 투자할 것인가, 일부 비공개 날짜의 위험을 감수할 것인가?

공개 정보는 공동 출발점을 만들고, 개인 구매는 판단의 차이를 만든다. 공개 선택은 기업 투자 선택·자리 선점과 별개이며, 특정 기업을 공개했다고 투자 의무가 생기지 않는다.

## 4. 총 4개 공용 정보의 순차 공개

### 진행 규칙
1. 서버가 6개 기업의 30일 차트를 생성한다. 모든 기업의 0일차와 산업 특성만 처음부터 공개한다.
2. 그 턴 자리 순서 A→B→C→D로 **각자 1회씩** 기업과 연속 5일을 고른다. 자리 순환과 입찰로 확정된 해당 턴 자리를 사용한다.
3. 선택 성공 즉시 5개 날짜 값을 전원에게 공개하고 다음 사람에게 넘긴다. 다음 사람은 앞사람의 선택과 결과를 보고 고른다.
4. 네 번째 공개가 끝난 뒤 개인 정보 구매·정보형 아이템 사용을 시작한다. 공개 선택은 무료이고 개인 구매권·코인을 소모하지 않는다.
5. 이후 기업 선택 → 투자 날짜·비중 결정 → 전체 차트 공개 → 정산으로 진행한다.

### 초기 제한과 예외
- 한 사람당 최대 **10초**, 총 최대 40초를 사용한다. INFO 90초 설정에서는 그 안에서 사용하여 개인 탐색에 최소 50초를 남긴다. 별도 40초를 덧붙이지 않는다. 선택을 확정하면 다음 사람에게 바로 넘어간다. 짧은 검사 설정은 `min(10초, INFO/5)`를 사용한다.
- 본인 차례에는 화면의 파란 테두리와 큰 상단 안내를 차례가 끝날 때까지 유지한다. 다른 사람 차례에는 현재 선택자를 표시한다. 확대 중에도 같은 안내와 타이머가 보인다.
- 공개 구간은 **이미 공용 공개된 날짜와 겹치지 않게** 한다. 4회 완료 시 정확히 20개 기업·날짜 값이 공개된다. 0일차 기준값은 이 수에 포함하지 않는다.
- 같은 기업을 여러 명이 골라도 된다. 기업별 공개 상한은 우선 두지 않는다. 다른 기업은 개인 구매로 탐색할 수 있다.
- 시간 초과·연결 끊김 시 서버가 유효 후보 중 하나를 자동 선택한다. 공용 공개 날짜가 적은 기업을 우선하고, 동률이면 공개된 고정 기업 순서, 날짜는 시작일 오름차순을 사용한다. 숨은 값이나 수익성을 보지 않는다.
- 유효 후보는 `1 <= 시작일 <= 26`이고 기존 공용 날짜와 겹치지 않는 5일 창이다. 네 번의 공개 동안에는 항상 후보가 남는다.
- 차례 밖 요청·중복 요청·마감 후 요청을 검증한다. 요청 재전송으로 두 번 공개되지 않으며, 재접속 시 현재 공개 내역·차례·마감을 복구한다.
- 공개 단계에는 개인 구매·정보 아이템·정보 공격을 허용하지 않는다. 모두 같은 공용 정보를 본 뒤 탐색을 시작한다.

### 심리전과 순서의 차이
- 먼저 고른 사람은 관심 기업의 정보를 확보하지만 관심을 드러낸다.
- 나중 사람은 앞의 결과를 이어 보거나, 아무도 확인하지 않은 기업으로 갈 수 있다.
- 다른 기업에 개인 코인을 써서 투자 대상을 바꿀 수 있으므로 공개 선택만으로 관심을 확정할 수는 없다.
- 네 명이 한 기업만 고르는 현상이 반복되면 **기업당 공개 최대 2회**를 후속 실험한다. 첫 버전부터 제한을 추가하지 않는다.

## 5. 정보 구매: 고정 묶음에서 이동 가능한 5일 창으로

| 방식 | 선택의 재미 | 부담·위험 | 판단 |
|---|---|---|---|
| 고정 5일 묶음 | 규칙이 단순함 | 고점·저점이 경계에 걸려도 선택을 조정할 수 없음 | 기존 비교군 |
| **원하는 위치의 연속 5일** | 빈틈 연결, 거래 후보 날짜 주변 확인 | 중복 날짜와 구매 범위 표시 필요 | **첫 구현 권장** |
| 3·5·8일 등 길이 선택 | 넓은 탐색과 정밀 탐색 구분 | 가격표·코인 경제가 복잡해짐 | 후속 실험 |
| 고점·저점 자동 탐지권 | 즉각적인 보상 | 시스템이 최적 투자 구간을 찾아주는 문제가 생김 | 기본 구매에서는 제외 |

처음에는 **정보 길이 5일은 유지하고, 구간의 위치를 선택하게 바꾸는 것**만으로 재미를 검증한다. 거래 가능한 보유 기간 5~10일은 별도 규칙으로 유지한다.

**5개 날짜 정보와 5일 보유는 다르다.** 예를 들어 3~7일의 다섯 값을 알아도 3→7일 보유는 4일이라 허용되지 않는다. 3→8일처럼 최소 6개 날짜에 걸친 두 끝점이 필요하다. 따라서 정보 한 번으로 거래 후보 양 끝을 항상 확인할 수는 없으며, 다른 공개 정보와 연결하거나 추가 구매 또는 미확인 끝점의 위험 감수가 필요하다. 이 특성이 지나치게 답답한지는 플레이 테스트로 확인한다.

### 개인 구매 규칙 초안
- 기업과 시작일을 골라 `[시작일, 시작일+4]`를 1코인에 구매한다. 시작일은 1~26 정수이며, 0일차는 항상 무료다.
- 차트에서 5일 선택 창을 이동하고 `9~13일 / 새 정보 4일 / 1코인`처럼 확인한 뒤 구매한다. 드래그만으로 코인을 차감하지 않는다.
- 공용·개인 열람 날짜와 **부분 중복은 허용**한다. 두 구간 사이의 빈틈이나 원하는 거래 후보 날짜를 확인할 수 있다.
- 신규 날짜가 하나도 없다면 구매를 거절하고 차감하지 않는다. 신규 날짜가 1~4일이어도 가격은 1코인이며 구매 전에 신규 날짜 수를 표시한다.
- 처음부터 날짜 수에 비례한 할인은 넣지 않는다. 코인 단위를 유지하고, 효율이 낮은 중복 구매는 플레이어가 판단한다.
- 다른 사람에게는 개인 구매 기업·날짜·값을 직접 공개하지 않는다. 공용 선택자와 선택 구간은 모두에게 표시한다.
- 구매 위치와 관계없이 원본 시장은 동일하다. 첫 개인 구매나 선택 기업에 맞춰 패턴을 유리하게 바꾸지 않는다.

### 실제 선택 예시
- 공용으로 AI 6~10일, AI 16~20일이 열렸다. 두 구간 모두 높은 값이지만 중간 움직임은 모른다.
- AI 11~15일을 사면 두 고점 사이의 하락과 반등을 확인할 수 있다. M자처럼 보였던 가설을 좁힐 수 있다.
- 다른 플레이어는 AI를 따라가지 않고 FOOD 3~7일을 사서 별도 거래 후보를 찾는다.
- AI 8~12일은 기존 공용 날짜와 겹치므로 신규 날짜가 2일이다. 같은 1코인이라도 11~15일보다 정보량이 적다. 다만 특정 거래 날짜를 확인하는 목적이라면 선택할 수 있다.

### 후속 대안: 정보 길이 선택
이동형 5일 창만으로 선택이 충분하지 않을 때 `3일=1코인, 7일=2코인` 등을 별도 테스트한다. 두 방식은 동시에 도입하지 않는다. 짧은 창은 진입·청산 주변 확인, 긴 창은 큰 흐름 확인에 유리하지만, 단순히 날짜당 가격이 가장 싼 상품만 고르는 게임이 되는지 검증해야 한다.

## 6. 차트 패턴을 거래 판단과 연결하기

패턴의 역할은 **숨은 날짜의 모양에 관한 가설을 만드는 것**이다. M자라고 항상 하락하지 않으며 W자라고 항상 수익이 나지 않는다. 같은 공개 구간에 여러 전체 차트가 들어맞도록 만든다.

| 패턴 | 전체 차트의 특징 | 추가로 확인할 만한 부분 | 투자 규칙과의 연결 |
|---|---|---|---|
| Rectangle / 박스권 | 일정 범위 안에서 고점·저점 반복 | 박스 하단 접근 뒤 반등 또는 이탈 구간 | 하단→상단이 5~10일 안에 있는지 확인 |
| Double Top / M자 | 두 고점 사이 조정, 두 번째 고점 이후 여러 경로 | 두 고점 사이 저점과 두 번째 고점 직후 | 고점 두 개만으로 하락 확정 금지. 하락 아이템과도 연결 가능 |
| Double Bottom / W자 | 두 저점과 중간 반등 | 두 번째 저점 뒤 회복 또는 추가 하락 | 저점→회복의 시간 간격과 실제 날짜 차이가 중요 |
| Flag / 깃발형 | 큰 상승·하락 뒤 짧은 조정 | 조정 종료와 재돌파·실패 구간 | 급등 직전부터 보유할 수 있는지, 5일 이전에 끝나는지 확인 |

### 모양만 다른 동일 정답을 피하기
- 패턴 전체를 30일에 늘여 그리지 않는다. 주 패턴은 예를 들어 12~22일 길이로 배치하고 앞뒤에 다른 움직임을 넣는다.
- 시작일·길이·진폭·기울기·좌우 비대칭을 바꾼다. 주요 저점이 매번 10일차에 나오면 안 된다.
- 첫 버전은 주 패턴 1개와 전후 흐름으로 제한한다. 30일에 여러 복잡한 패턴을 겹치지 않는다.
- 거래 가능 구간을 전수 계산하여 '3일짜리 급등만 있고 합법적인 5~10일 거래에서는 의미 없는 차트'가 과도하지 않은지 확인한다.
- 모든 기업에 큰 수익 구간을 보장하지 않는다. 실제 게임의 양방향 아이템 유무를 고려해 한 기업에 기회가 몰리는 빈도를 점검한다.

### 완성·실패·유사 패턴
초기 생성 비중의 예시는 `형태가 완성된 패턴 50% / 실패·훼손된 패턴 30% / 뚜렷한 패턴 없는 추세·횡보 20%`다. 이는 게임용 생성 비중이며 현실 통계나 플레이어에게 제시하는 성공 확률이 아니다.

같은 M자 앞부분 뒤에 하락·재상승·횡보가 모두 가능하도록 **턴 시작에 전체 경로를 먼저 결정**한다. 공개 이후의 매수 행동에 맞춰 성공·실패를 추첨하지 않는다. 생성용 유형은 서버 내부 정보이며 시장 공개 전 클라이언트에 보내지 않는다.

## 7. 기업별 개성과 확장 패턴

기업에 특정 정답을 고정하지 않고 출현 가중치와 진폭으로 구분한다.

| 기업 | 성격 | 첫 4종 중 가중치를 높일 패턴 | 후속 확장·이벤트 연출 |
|---|---|---|---|
| AI | 성장 기대·과열, 큰 변동 | Flag, Double Top | 상승삼각형, 계단 상승, 모델 발표·경쟁 기술 |
| SPACE | 안정 구간 뒤 큰 변화 | Rectangle, Flag | V 반등, 갭, 발사 성공·실패·연기 |
| FOOD | 낮은 변동, 완만한 회복 | Rectangle, Double Bottom | 둥근 바닥, 원재료·유통 계약 |
| AUTO | 순환과 회복 | Double Bottom, Double Top | 헤드앤숄더, 판매량·리콜 |
| BIO | 이벤트 중심의 급격한 변화 | Flag, Double Top, Double Bottom | V 반전, 임상·승인·연구 중단 |
| BANK | 낮은 변동, 완만한 추세 | Rectangle, Double Top | 둥근 바닥, 금리·부실 대출 |

산업명과 변동성 성격은 모두에게 공개해 아무 정보가 없는 기업도 선택할 근거를 준다. 실제 발사 성공·임상 실패처럼 방향을 알려주는 뉴스는 추가 정보이므로 첫 버전에서는 **전체 시장 공개 후 설명 연출**로 사용한다. 거래량과 사전 뉴스는 데이터·공개 비용을 설계한 뒤 추가한다.

확장 후보는 Triangle, Head and Shoulders, V 반전, Island Reversal 등이다. 원문의 Thomas N. Bulkowski, Encyclopedia of Chart Patterns 참고는 패턴 명칭과 형태를 정리하는 용도로 유지하며 책의 성공률을 게임 확률로 가져오지 않는다. 갭과 Island Reversal은 OHLC 도입 이후로 미룬다.

## 8. 생성 알고리즘 구체화

### 현재 변화율 배열을 사용하는 1차 구현
1. 방 시드·턴·기업을 기준으로 재현 가능한 난수 스트림을 만든다. 차트 생성과 공개 선택용 처리를 분리하여 공개 행동이 가격 난수열을 바꾸지 않게 한다.
2. 기업별 가중치로 패턴 유형, 완성/실패/비패턴 분기, 시작일·길이·진폭을 뽑는다.
3. 정규화한 시간·높이 제어점을 실제 날짜·기준 대비 bps로 변환한다. M자는 두 봉우리와 사이 저점을 두되 높이를 완전히 같게 만들지 않는다.
4. 제어점 사이를 우선 선형 보간한다. 고급 보간으로 의도하지 않은 고점이 생기는 문제를 피한다.
5. 앞뒤 흐름과 작은 노이즈를 추가하고 0일차 값은 0으로 고정한다. 시장 공통 흐름을 약하게 섞는 것은 후속 확장으로 둔다.
6. 기업별 일일 변화 한계와 기준 대비 상한을 검증한다. 초과분을 무조건 clamp해 긴 평평한 천장·바닥을 만들기보다 진폭을 줄이거나 후보를 재생성한다.
7. 재생성은 최대 20회 등 상한을 두고, 실패하면 제약을 만족하는 단순 추세·횡보 경로로 대체한다. 패턴 이름을 억지로 붙이지 않는다.
8. 전체 경로를 서버에 고정 저장한 뒤 공용 공개를 진행한다. 개인 구매는 같은 배열에서 허용 날짜만 읽는다.

기본 생성 좌표는 **0일차 대비 변화율(bps)**다. 원문의 `close[t-1] * (1 + return[t])`를 기존 정산 데이터에 그대로 대입하지 않는다. 가격 표현이 필요하면 별도의 표시 기준가에 `price[t] = basePrice * (1 + changeBps[t] / 10000)`를 적용한다.

### 변동성의 초기 기준
기존 구현의 한계를 출발점으로 유지하고 패턴 진폭을 이 안에 맞춘다. 아래 값은 현실 통계가 아니라 현재 게임 설정이다.

| 기업 | 1턴 일별 변화 한계 | 0일차 대비 범위 |
|---|---|---|
| AI | ±8%p | ±50% |
| SPACE | ±8%p | ±50% |
| FOOD | ±1.2%p | ±8% |
| AUTO | ±3.5%p | ±20% |
| BIO | ±15%p | ±80% |
| BANK | ±0.8%p | ±6% |

일별 한계는 기존처럼 턴당 5%씩 증가하고 전체 범위는 유지한다. 원문의 이벤트 ±20~45% 등 별도 점프 폭은 일일 한계를 바꾸는 규칙이므로 이번 기본안에 혼합하지 않는다. 이벤트 예외는 별도 밸런싱 과제다.

### OHLC는 2차 확장
첫 버전은 일별 변화율 차트에서 패턴과 탐색 재미부터 검증한다. 이후 캔들을 넣으면 종가는 정산 기준 경로와 일치시키고 시가·고가·저가는 별도 생성한다. 항상 `high >= max(open, close)`, `low <= min(open, close)`, 모든 가격 양수를 보장한다. 캔들의 장중 저가·고가를 거래 체결 가격으로 쓸 수 있는지는 별도 규칙이며 자동으로 허용하지 않는다.

## 9. 정보량과 시간 밸런스

- 기존 무료 정보: 6개 기업 × 2묶음 × 5일 = **60개 기업·날짜 값**.
- 새 공용 정보: 4회 × 5일 = **20개 값**. 기존의 1/3이므로 공개 횟수만 바꾸면 탐색 난도가 크게 오른다.
- 기존 지급을 유지하면 1~5턴에는 개인 3코인으로 최대 15일, 6~10턴에는 5코인으로 최대 25일을 추가 확인한다. 그 턴 지급분만 쓰고 이월·능력·아이템·중복을 제외한 계산이다.
- 기업별 정보량은 공개 선택에 따라 달라진다. '정보가 없는 기업을 아무도 탐색하지 않는 현상'과 '공개가 많은 기업에 모두 몰리는 현상'을 함께 관찰한다.

첫 비교는 코인 지급 3/5개·정보 1코인을 유지하여 공개/구매 방식의 효과를 확인한다. 탐색 부족이 반복되면 초반 지급을 4개로 높이는 실험을 하고, 시간 부족이면 선택 UI와 탐색 시간을 먼저 점검한다. 공개 수를 늘리거나 모든 차트의 정답을 쉽게 만드는 방식으로 보정하지 않는다.

15~20분은 원문의 목표 플레이타임이지만 10턴×최대160초만으로도 약 26분 40초다. 공개 절차는 INFO 예산 안에 넣고 실제 평균 턴 시간을 측정한다. 목표 시간 충족 여부는 조기 완료와 입찰·능력 선택 시간을 포함해 확인해야 한다.

## 10. 데이터·네트워크·아이템 연동 설계

고정 묶음 인덱스는 임의 시작일 구간을 표현하기 어렵다. 다음은 기존 계약을 수정할 때의 방향이며 완성 API가 아니다.

```csharp
public enum InformationSource { Public, Purchased, Ability, Item, Stolen }

public sealed class InformationWindowRequest {
    public string requestId;
    public string companyId;
    public int startDay; // 서버 검증: 1..26, length는 첫 버전에서 5로 고정
}

// 일별 열람 여부와 구매 기록을 분리한다.
// 공용 마스크: 기업별 day 0..30
// 개인 마스크: 플레이어·턴·기업별 day 0..30
// 구매 기록: recordId, 요청자, companyId, startDay, length, source, paidCoins
```

- 열람 가능 날짜는 **공용 마스크와 개인 마스크의 합집합**이다. 잠금 표시도 6묶음이 아닌 일별 마스크에서 만든다.
- 공용 공개 기록에는 선택자·자동 선택 여부·차례를 저장한다. 서버가 차례와 마감을 관리한다.
- 개인 응답에는 허용 날짜 값만 넣는다. 숨은 값, 패턴 유형, 제어점, 시장 재현이 가능한 시드를 클라이언트에 보내지 않는다.
- 가려진 날짜는 `null`로 표시하고 그 사이를 선으로 연결하지 않는 현재 그래프 원칙을 유지한다. Y축도 비공개 원본의 최대·최솟값으로 정하지 않는다.
- 블랙박스·정보상 무료 구매도 같은 5일 창을 사용하고 신규 날짜가 없으면 소모하지 않는다. 정보상의 추가 무료 창은 첫 창 처리 후 남은 미열람 날짜를 기준으로 검증한다.
- 정보 훔치기는 유료 구매 **기록** 중 신규 날짜가 있는 기록을 대상으로 한다. 복사 날짜는 STOLEN 출처로 기록하며 다시 훔칠 원본이 되지 않는다.
- 정보 왜곡은 대상의 유료 기록 1개가 제공한 날짜 중 다른 공용·개인 열람 근거가 없는 날짜만 일시 가린다. 겹치는 다른 구매·아이템으로 확인한 날짜까지 지우지 않는다. 가릴 날짜가 전혀 없는 대상은 거절한다.
- 같은 날짜의 열람 근거가 여러 개일 수 있으므로 단일 출처 문자열만 덮어쓰지 않는다. 실제 코인을 낸 기록과 무료·아이템 기록을 구분한다.
- 새 요청 타입·DTO와 규칙 버전을 함께 정리하고 BOT·fixture·재접속 스냅샷도 새 날짜 마스크를 따르게 한다. 기존 `bundleIndex` 필드에 시작일을 넣어 의미만 바꾸지 않는다.

## 11. 구현 순서와 검증 기준

### 구현 순서
1. 패턴 생성만 기존 무작위 생성기 옆에 별도 구현한다. Rectangle·DoubleTop·DoubleBottom·Flag 네 종류로 제한한다.
2. 임의 시작일 5일 창과 일별 열람 원장을 도입한다. 공개/개인 열람·부분 중복·아이템 처리를 함께 맞춘다.
3. 기업별 무료 2묶음 검증·자동 추첨을 제거하고 INFO 안에 공용 선택 4회를 연결한다. 공용 공개 종료 전 조기 완료로 단계가 넘어가지 않게 한다.
4. 그래프 선택 창·신규 날짜 수·차례·자동 선택 표시를 연결한다. BOT은 허용 정보만 사용한다.
5. 이후 캔들·거래량·뉴스·가변 길이 구매를 각각 독립 실험한다.

### 구현 시 필요한 검증
- 같은 시드·턴·기업이면 같은 차트이며 공개 순서·구매 순서·재접속이 원본 값을 바꾸지 않는다.
- 0일차는 항상 0, 일별 한계·기업별 범위를 만족한다. 패턴 재생성은 종료하며 대체 경로도 유효하다.
- 공용 공개는 총 4회·각 플레이어 1회이고, 중복 없는 20개 값이 모든 플레이어에게 동일하게 보인다. 시간 초과·이탈·요청 재전송에도 성립한다.
- 구매 창은 1~26일 시작, 5일 길이만 허용한다. 26~30은 허용하고 27~31은 거절한다.
- 완전 중복은 비용·무료권 차감 없이 거절한다. 부분 중복은 미리 표시한 가격으로 한 번만 차감하고 합집합으로 표시한다.
- 공용 날짜·다른 개인 열람 근거가 정보 왜곡으로 사라지지 않는다. 훔치기와 무료권이 중복 날짜를 새 유료 구매로 기록하지 않는다.
- 기존 날짜·보유 기간·정산 공식은 유지한다. 전체 공개 전 네트워크 응답과 UI 축에 비공개 값이 새지 않는다.

### 플레이 테스트에서 볼 지표
| 지표 | 확인하려는 문제 | 조정 후보 |
|---|---|---|
| 기업별 공용·개인 탐색 비율 | 한 기업 집중, 미탐색 기업 방치 | 기업당 공개 상한 실험, 코인 지급량 |
