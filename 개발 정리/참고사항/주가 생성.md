# 주가 생성

작성 기준: 2026-11-13 현재 작업 트리의 코드. 현재 구현된 주가 생성 요소를 정리한 문서이며, 향후 시장 이벤트 계획과는 구분한다.

현재 게임은 **시드·턴·기업별 난수로 패턴 기반 30일 경로를 생성한 뒤, BANK와 BIO에 별도 보정을 적용**한다. 플레이어의 매수·매도나 정보 구매로 시장 가격이 바뀌는 구조는 아니다.

## 1. 실제 게임의 생성 순서

1. `DevTabletBootstrap`에서 `RandomMarketGenerator.NewSeed()`로 방의 시드를 정한다.
2. `MarketService.CreateStockSystem(seed)`가 턴별 시장 공급자를 구성한다.
3. `GenerateStockMarket(seed, turn)`이 `PatternMarketGenerator.Generate(seed, turn)`을 호출한다.
4. 기업마다 생성 분기, 패턴 종류, 배치 구간, 진폭, 기울기, 비대칭과 노이즈를 결정한다.
5. 전체 경로를 축소해 기업별 누적 범위와 일일 변동 한도를 맞추고 정수로 반올림한다.
6. BANK에는 변동폭 압축, BIO에는 연구 이벤트 효과와 추가 범위 보정을 적용한다.
7. 턴 시작 시 `MarketBook`에 복사해 보관하고, 게임은 이 고정된 값을 열람·거래·정산에 사용한다.

현재 주식 게임은 6턴이다(`StockRules.Turns`). 기반 패턴 생성기와 실험실은 1~10턴을 지원한다. 각 턴은 30일이며, 직전 턴 종가를 이어 붙이지 않고 0일차를 다시 0으로 시작한다.

## 2. 저장값과 가격의 의미

- `dailyChangesBps`는 0~30일의 31개 정수 값이다.
- 각 값은 **0일차 대비 누적 등락률**이다. 전날 대비 등락률이 아니다.
- 1bps = 0.01%포인트, 100bps = 1%포인트이며 0일차 값은 0이다.
- 정산에서 사용하는 가격 기준은 `10000 + dailyChangesBps[day]`이다.
- 예를 들어 값이 500이면 기준 가격 10000 대비 +5%, 값이 -500이면 -5%다.
- 시가는 전날 종가다. 별도의 시가 갭·고가·저가·거래량 생성은 없다.
- 아래의 일일 한도는 `|오늘 누적값 - 전날 누적값|`의 한도다. 전날 실제 가격을 분모로 계산한 수익률 한도와는 다르다.

## 3. 시드·턴·기업과 난수

| 입력 | 가격 경로에 미치는 영향 |
| --- | --- |
| 방 시드 | 해당 방의 모든 턴에 쓰이는 재현 가능한 난수의 출발점 |
| 턴 번호 | 난수 경로와 일일 변동 한도, BIO 이벤트 확률·결과를 변경 |
| 기업 ID | 패턴 선택 가중치, 기본 일일 한도, 누적 한도, 기업별 보정을 결정 |
| 기업 배열의 위치 | 기업별 난수 초기 상태에 포함되므로 배열 순서를 바꾸면 같은 시드의 경로도 변경 |

현재 기업 배열 순서는 `AI, SPACE, FOOD, BANK, BIO, AUTO`다. 패턴 생성기는 시드·턴·기업 위치에 서로 다른 상수를 곱하고 XOR로 섞어 기업별 SplitMix64 방식의 난수 스트림을 만든다. 기업 사이에 하나의 난수 스트림을 공유하지 않는다.

같은 코드·시드·턴·기업 배열이면 같은 값이 나온다. 조회 시각·조회 순서·접속 인원은 가격 생성 입력이 아니다. 기업별 스트림은 분리되어 있지만, 공통 시장 요인이나 기업 간 상관관계를 별도로 모델링하지는 않는다.

이 문서의 확률은 코드의 정수 난수 구간에 따른 설계 비중이다. 패턴 생성기의 정수 난수는 나머지 연산으로 구간에 매핑하므로 수학적으로 완전히 균등한 추출과는 극미세한 차이가 있다. 고정 시드에서는 이미 결정된 결과이며, 소수의 기업·턴에서 비율이 정확히 맞춰지는 할당 방식도 아니다.

## 4. 완성·훼손·비패턴 분기

매 턴 각 기업에 대해 `0~99` 정수를 뽑아 분기를 선택한다. 기업마다 같은 분기 비중을 사용한다.

| 난수 구간 | 분기 | 설계 비중 | 처리 |
| --- | --- | --- | --- |
| 0~49 | 완성 `Completed` | 50% | 선택된 패턴의 기본 제어점을 사용 |
| 50~79 | 훼손 `Damaged` | 30% | 기본 패턴의 마지막 두 제어점을 교체 |
| 80~99 | 비패턴 `Unstructured` | 20% | 패턴 모양을 더하지 않고 기울기와 노이즈로 생성 |

**완성 50%는 눈으로 명확하게 패턴이 보일 확률이나 투자 성공률을 뜻하지 않는다.** 완성 분기에도 기울기·노이즈가 섞이고 BANK·BIO는 이후 보정도 받는다. 훼손 분기 역시 반드시 손실로 끝난다는 뜻은 아니다. 비패턴 경로에서도 우연히 특정 패턴과 비슷한 모양이 나올 수 있다.

비패턴 분기에서도 내부적으로 패턴 종류와 배치 정보는 추출한다. 다만 해당 모양을 가격에 더하지 않는다. 따라서 진단 메타데이터에 패턴 이름이 있어도 실제로 그 패턴이 삽입되었다는 뜻은 아니다.

## 5. 기업별 패턴 선택 비중

분기와 별도로 기업별 가중치에 따라 주 패턴 하나를 선택한다. 한 기업의 한 턴에 여러 주 패턴을 의도적으로 배치하는 방식은 아니다.

공통 4종에 합계 50%, 그 기업의 특화 2종에 각각 25%를 배정한다. 아래 확률은 완성·훼손·비패턴 분기 전 선택 비중이다. 예를 들어 BANK에서 박스권을 뽑고 완성 분기로 들어갈 비중은 20% × 50% = 10%다.

| 기업 | 박스권 | M자 | W자 | 깃발형 | 특화 A · 25% | 특화 B · 25% | 일부 공개 시 겹치는 단서 |
| --- | ---: | ---: | ---: | ---: | --- | --- | --- |
| BANK | 20% | 20% | 5% | 5% | 상승 삼각형 | 하락 삼각형 | 한쪽 경계를 재시험하는 동안은 좁은 박스권처럼 보인다. |
| FOOD | 20% | 5% | 20% | 5% | 원형 바닥 | 원형 천장 | 수요가 완만하게 회복·둔화되는 중앙부는 횡보와 닮는다. |
| AUTO | 5% | 20% | 20% | 5% | 상승 측정 이동 | 하락 측정 이동 | 경기 순환의 첫 파동과 중간 조정까지는 깃발형과 닮는다. |
| AI | 5% | 20% | 5% | 20% | 범프 앤 런 천장 | 헤드 앤 숄더 천장 | 초기 상승 후 눌림은 깃발형, 첫 두 봉우리는 M자로도 읽힌다. |
| SPACE | 20% | 5% | 5% | 20% | 페넌트 | 세 개의 상승 골짜기 | 계약 기대 후 수렴은 깃발처럼, 초기 두 저점은 W처럼 보인다. |
| BIO | 5% | 15% | 15% | 15% | V자 바닥 | V자 천장 | 발표 전 급락·급등만 보면 추세가 이어질지 반전할지 알기 어렵다. |

원전은 Thomas N. Bulkowski의 *Encyclopedia of Chart Patterns* 제3판이다. 게임에서는 일별 종가 제어점으로 모양을 축약한다. 위 확률과 기업 배정은 게임 밸런스 값이다. [저자의 패턴 그림 색인](https://www.thepatternsite.com/visualcpindex.html)

## 6. 기본 패턴의 모양

패턴은 아래 상대 높이의 제어점을 시간순으로 연결한다. 값 자체가 등락률은 아니며, 이후 진폭을 곱한다.

| 패턴 | 상대 높이 제어점 | 의도된 기본 흐름 |
| --- | --- | --- |
| 박스권 | `0 → 0.85 → -0.65 → 0.95 → -0.8 → 0.75 → 0.1` | 위아래를 반복한 뒤 중심 부근으로 복귀 |
| M자 | `0 → 1 → 0.25 → r → -0.4 → -0.85` | 두 고점 형성 후 하락, `r = 0.85~1.15` |
| W자 | `0 → -1 → -0.25 → -r → 0.4 → 0.85` | 두 저점 형성 후 상승, `r = 0.85~1.15` |
| 깃발형 | `0 → s → 0.7s → 0.8s → 0.55s → 1.6s` | 급변·조정 후 같은 방향으로 진행, `s = -1 또는 +1` |

M/W의 두 번째 고점·저점 배율은 0.01 단위로 추출한다. 깃발형은 상승·하락 방향을 각각 약 50%로 선택한다. 박스권에는 별도의 상방·하방 돌파 분기 선택이 없다.

훼손 분기에서는 마지막에서 세 번째 제어점의 높이를 기준으로 아래와 같이 교체한다.

- 끝에서 두 번째 높이: `기준 높이 + (-0.30~+0.30)`.
- 마지막 높이: `기준 높이 + (-0.55~+0.55)`.
- 두 난수는 각각 0.01 단위다. 후반부가 반전·횡보·연장될 수 있으며, 최종 형태를 판정해서 재생성하지 않는다.

## 7. 패턴 배치 시점과 비대칭

| 요소 | 코드 범위·계산 | 영향 |
| --- | --- | --- |
| 시작일 | 1~7일 정수 | 패턴이 시작되는 위치 |
| 길이 | 12~22 정수, `min(길이, 29 - 시작일)` | 제어점 사이 전체 시간 길이 |
| 종료일 | 시작일 + 길이, 현재 범위에서 13~29일 | 이후 꼬리 구간의 시작 |
| 내부 제어점 시각 | `시작일 + 길이 × (k + j) / (제어점 수 - 1)` | 봉우리·골 사이의 시간 비대칭 |
| 시각 흔들림 `j` | -0.20~+0.20, 0.01 단위 | 좌우 폭이 똑같은 도형이 되지 않도록 조정 |

첫 제어점은 시작일, 마지막 제어점은 종료일에 고정한다. 중간 값은 제어점 사이를 선형 보간해 얻는다. 생성은 매끄러운 곡선 보간이 아니라 직선 구간의 연결이다.

시작 전에는 패턴 성분이 0이다. 종료 시점부터는 `마지막 높이 + (현재일 - 종료일) × 꼬리 난수`를 사용한다. 꼬리 난수는 **매 날짜 새로** -0.08~+0.08을 0.01 단위로 뽑는다. 일정한 기울기의 연장선이나 누적 랜덤워크와는 다르다.

## 8. 진폭·기울기·노이즈

아래에서 `L`은 해당 기업·턴의 일일 한도, `C`는 기업별 누적 한도다.

| 요소 | 계산 | 영향 |
| --- | --- | --- |
| 패턴 진폭 `A` | `min(C × 0.35~0.75, L × 2.0~3.8)` | 패턴 자체의 크기. 앞쪽 배율은 0.01, 뒤쪽 배율은 0.1 단위로 각각 추출 |
| 고정 기울기 `D` | `L × (-0.35~+0.35)` | 30일 전체의 상승·하락 추세. 배율은 0.01 단위 |
| 누적 노이즈 `W[d]` | `W[d-1] + L × 0.24 × u[d]` | 시간이 지나며 누적되는 불규칙한 흐름 |
| 당일 노이즈 `N[d]` | `L × 0.10 × v[d]` | 하루 단위의 짧은 흔들림 |

`u[d]`, `v[d]`는 각각 -1.00~+1.00을 0.01 단위로 추출한다. 기울기는 기업·턴마다 한 번 정하고, 두 노이즈는 날짜마다 추출한다.

보정 전 경로는 다음과 같다.

```text
raw[0] = 0
raw[d] = 패턴높이[d] × A + D × d + W[d] + N[d]   (d = 1~30)
```

비패턴 분기는 `패턴높이[d] = 0`이다. 완성·훼손 분기에도 기울기와 두 노이즈가 항상 더해진다. 따라서 패턴 제어점이 위쪽이어도 전체 추세에 밀려 음수 가격 등락률 영역에 위치할 수 있다.

## 9. 기업별 한도와 턴 증가

| 기업 | 1턴 일일 한도 `L` | 누적 한도 `C` | 패턴 생성 단계의 축소 목표 `0.96C` |
| --- | --- | --- | --- |
| BANK | 80bps / 0.8%p | ±600bps / ±6% | ±576bps / ±5.76% |
| FOOD | 120bps / 1.2%p | ±800bps / ±8% | ±768bps / ±7.68% |
| AUTO | 350bps / 3.5%p | ±2000bps / ±20% | ±1920bps / ±19.2% |
| AI | 800bps / 8%p | ±5000bps / ±50% | ±4800bps / ±48% |
| SPACE | 800bps / 8%p | ±5000bps / ±50% | ±4800bps / ±48% |
| BIO | 1500bps / 15%p | ±8000bps / ±80% | ±7680bps / ±76.8% |

일일 한도는 `round(기본 한도 × (1 + 0.05 × (턴 - 1)))`이며 0.5는 올림한다. 예를 들어 AUTO 2턴은 367.5 → 368bps다. 매 턴 이전 한도에 1.05를 곱하는 복리 증가가 아니라 **기본 한도 대비 선형 증가**다. 6턴은 기본의 1.25배, 10턴은 1.45배다. 누적 한도는 턴에 따라 증가하지 않는다.

패턴 생성기는 날짜별 값을 상·하한에 잘라 붙이지 않고, 30일 전체에 같은 축소율을 적용한다.

```text
scale = min(
    1,
    모든 날짜의 0.96 × C / |raw[d]|,             // 분모 0 제외
    모든 날짜의 (L - 1) / |raw[d] - raw[d-1]|    // 분모 0 제외
)
result[d] = round(raw[d] × scale)
```

정수 반올림은 `MidpointRounding.AwayFromZero`다. 일일 제약에 1bps의 여유를 둔다. 한 날짜의 큰 값이나 급격한 움직임 때문에 **다른 모든 날짜도 함께 축소**될 수 있다. 위 목표는 축소·반올림 전 기준이며, 최종 정수에는 반올림이 적용된다. 반복 추첨이나 형태 재검사는 없다.

## 10. 현재 주식 게임의 BANK 보정

패턴 생성이 끝난 뒤 BANK의 각 날짜 값 `v`를 다음과 같이 변환한다.

```text
BANK[d] = (int)(200 × tanh(v / 2500))
```

- `int` 변환은 소수점을 0 방향으로 버린다.
- 양수·음수 방향을 유지하면서 변동폭을 크게 줄이는 비선형 압축이다.
- 함수 자체는 ±200bps(±2%)에 접근하지만, 앞 단계의 BANK 입력이 약 ±576bps 이내라 실제 출력은 대략 ±45bps(±0.45%) 수준까지다.
- 패턴 종류와 분기를 다시 추첨하지 않는다. 원래 형태를 압축하므로 정수 변환 후 일부 날짜가 같은 값으로 보일 수 있다.
- BANK의 실제 경로를 기본 누적 한도 ±6%와 같은 크기로 해석하면 안 된다.

## 11. 현재 주식 게임의 BIO 연구 이벤트

BIO에는 기본 패턴과 별개로 연구 이벤트 효과가 추가된다.

### 확률과 결과

- `확률bps = 3500 + StockHash(seed, turn, 17) % 4001`.
- 표시되는 성공 확률 범위는 35.00~75.00%이며, 시드·턴으로 고정된다.
- `StockHash(seed, turn, 53) % 10000 < 확률bps`이면 성공, 아니면 실패다.
- 성공 효과는 `+1800bps`, 실패 효과는 `-1600bps`다.
- 서로 다른 salt 17과 53으로 확률과 판정값을 구한다. 실행 중 새 난수로 재추첨하지 않는다.
- 패턴 완성·훼손·비패턴 분기와는 별도의 조건이다. 완성 패턴 + 연구 실패, 비패턴 + 연구 성공도 가능하다.

### 반영 시점과 추가 축소

```text
eventRaw[d] = 기본BIO[d] + effect × max(0, d - 12) / 18.0
```

이벤트 가산분은 0~12일에 0이며, 13일부터 선형으로 늘어나 30일에 효과 전체가 반영된다. 하루에 한 번 급등·급락시키는 방식은 아니다.

가산 후에는 30일 전체에 다시 같은 축소율을 적용해 절댓값 7600bps와 일일 차이 `L - 1` 안에 들어오도록 한다. 이후 `Math.Round` 기본 방식(정확한 중간값은 짝수 쪽)으로 정수화한다.

따라서 연구 성공이어도 최종 종가나 투자 수익이 양수라는 보장은 없다. 또한 **후반부 이벤트 때문에 전체 축소율이 바뀌면, 이벤트 가산분이 0인 1~12일 값도 기본 생성기와 달라질 수 있다.** `BIO_RESEARCH` 증강은 확률을 보여줄 뿐, 확률·판정·가격을 바꾸지 않는다.

## 12. 가격 경로와 별도로 작동하는 요소

다음 요소는 현재 원본 주가 배열을 수정하지 않는다.

| 요소 | 실제로 바뀌는 것 |
| --- | --- |
| 매수·매도, 보유량, 잔여 공급량, BOT 주문 | 플레이어의 보유·거래 가능 여부와 투자 결과. 수요·공급에 따른 가격 충격은 없음 |
| 실시간 진입·청산 시각, 수량, 현금 배분 | 어떤 날짜의 가격으로 수익을 얻는지 |
| 공용 공개, 개인 정보 구매, 정보 아이템 | 열람 가능한 날짜·정보 기록·비용 |
| TREND·CONTRARIAN | 직전 턴 조건에 따라 이번 턴 초반 정보를 추가 열람. 이번 턴 가격의 추세를 강제하지 않음 |
| BIO_RESEARCH | 이미 정해진 연구 성공 확률의 열람 |
| SPACE_PIONEER·LONG_TERM·DIVERSIFY·CASH_INTEREST | 개인 정산의 보너스·손실 완화·현금 이자 |
| 나머지 증강 | 정보 할인 등. 차례를 전제로 한 선점과 기존 12주 집중 투자 증강은 후보에서 제외 |
| 재접속, 조회 순서, 일시정지, 진행 속도 | 연결 상태·공개 시점·진행 시간 |

플레이어별 수익이나 증강 효과가 서로 달라도 시장의 원본 가격은 공통이다. 현재 가격 생성에는 뉴스·거래량·호가·거시경제·공통 시장 이벤트·앞선 턴의 가격 추세를 원인으로 넣는 로직이 없다. 별도 계획 문서의 기능은 구현되기 전까지 생성 요소로 계산하지 않는다.

### 정보 탐색과 60초 매매

- 정보 탐색은 기본 30초다. 순서대로 기업을 선택하면 서버가 해당 기업의 미공개 연속 5일을 무료로 공개한다. 시작일은 1~26일이며, 남은 참가자가 모두 같은 기업을 선택해도 5일씩 받을 수 있는 후보 중에서 추첨한다. 개인 정보 구매에서는 원하는 날짜를 직접 고른다.
- 공용 공개가 끝난 뒤 정보 구매 화면에서 기업 차트의 날짜 구간을 선택하고 **예약하기**를 누른다. 개인 예약은 서버에 저장되고, 본인의 매매 차트에 띠로 표시된다. 실제 주문은 플레이어가 매매 버튼을 누를 때 체결된다.
- 정보 탐색 직후 전원이 보유 0주로 동시에 매매를 시작한다. 개인 보유 한도는 총 30주, 기업당 10주다. 서버 접수 순서로 기업의 남은 물량을 확인하며, 매도 수량은 즉시 시장에 돌아온다. BANK도 직접 사고팔 수 있다.
- 실제 체결은 모든 참가자의 해당 기업 차트에 표시된다. 같은 날짜 안에서 참가자마다 색과 가로 위치를 나누고, 매수는 상단 실선, 매도는 하단 점선으로 그린다. 재접속하면 현재 턴의 체결 기록과 본인 예약을 다시 받는다.
- 매매 시작 후 2초에 1일차, 4초에 2일차, 60초에 30일차 종가가 여섯 기업에 동시에 공개된다. 이미 본 미래 날짜는 그대로 보인다. 일시정지 중에는 서버 시계와 체결이 함께 멈춘다.
- 0일차에는 기준 가격, 이후에는 서버가 주문을 받은 시점의 최신 공개 종가에 진입·청산한다. 예를 들어 2초 경계에 도착한 진입은 1일차 종가로 처리되어 2일차 변동부터 손익에 반영된다. 30일차 종가로 남은 수량을 평가하고 매매를 마친다.
- **모두 진입**은 기업 잔여 물량, 개인 총 잔여 한도, 기업별 잔여 한도 중 최솟값만큼 매수한다. **진입**과 **청산**은 그래프 아래에서 맞춘 수량만큼 현재 포지션을 바꾼다. **모두 청산**은 현재 포지션을 0주로 만든다. 청산한 수량은 같은 턴에 다시 진입할 수 있다. 각 칸은 진입한 날의 가격 변화만 누적하며, 청산 후 재진입하면 기존 칸의 평가액을 이어 쓴다.

## 13. 같은 가격이 다르게 보이는 이유: 차트 표시

`ChartVerticalRange`는 열람 가능한 시가·종가와 공개 기준값 0만 받아 Y축을 계산한다.

```text
min, max = 열람값과 0의 최솟값·최댓값
span = max(50bps, max - min)
center = (min + max) / 2
표시 하한 = center - span × 0.62
표시 상한 = center + span × 0.62
```

- 일반적인 범위에서는 위·아래에 각각 범위의 12% 여백이 붙는다.
- 값이 없거나 평탄하면 최소 62bps 폭의 유효 표시 범위가 생긴다.
- 숨은 전체 고점·저점이나 기업별 한도는 축 계산 입력으로 사용하지 않는다.
- 추가 정보로 고점·저점을 알게 되면 축이 바뀌어 기존 움직임도 더 작거나 크게 보일 수 있다.
- 캔들/종가선 전환, 차트 확대, 패턴 구간 강조는 원본 가격에 영향을 주지 않는다.
- 캔들은 전날 종가~당일 종가 몸통을 표시한다. 고가·저가 꼬리를 별도로 생성하지 않는다.

## 14. 패턴 실험실과 현재 게임의 차이

실험실은 `PatternMarketGenerator.Inspect`를 사용한다.

| 경로 | 출력 |
| --- | --- |
| 실험실 일반 게임 생성 모드 | 기반 패턴 생성기의 원본 6종목 |
| 실험실 패턴별 비교 모드 | 기업 하나에 16종 패턴 × 3분기를 강제로 지정한 48개 진단 샘플 |
| `MarketService.CreateRandom` | 기반 패턴 생성기 사용, BANK·BIO 추가 보정 없음 |
| 현재 게임의 `MarketService.CreateStockSystem` | 기반 패턴 생성 후 BANK·BIO 추가 보정 |

강제 비교 모드는 실제 확률에 따른 표본 분포가 아니다. 지정한 생성 조건을 비교하기 위한 기능이며, 48개 샘플에서 각 분기의 등장 횟수로 실제 발생 확률을 판단하면 안 된다. 분기·패턴을 강제하면 이후 난수 소비가 달라질 수도 있어 모든 세부 노이즈까지 동일하게 통제하는 비교도 아니다.

강제 인자 없이 같은 시드·턴으로 호출한 `Inspect`와 `Generate`는 같은 기업별 원본 경로를 만든다. 다만 실험실에는 BANK·BIO 보정이 없으므로 **현재 게임과 BANK·BIO의 날짜별 가격이 다를 수 있다.** FOOD·AUTO·AI·SPACE는 현재 별도 후처리가 없다.

[PATTERN_LAB.md](PATTERN_LAB.md)의 “실제 일반 게임과 같은 값” 설명과 기존 일치 검증은 기반 패턴 생성기 기준이다. 현재 주식 게임의 보정까지 포함하는 일치 검증으로 해석하면 안 된다. 패턴 유형·분기·시드·배치 날짜는 개발용 진단 정보이며 플레이어용 네트워크 DTO에 추가하지 않는다.

## 15. 이전 생성기와 수정 지점

`RandomMarketGenerator.Generate`와 `SeededMarketProvider`는 이전 랜덤워크·비교용 구현이다. 기본적으로 전날 값에 무작위 증감을 더하고 누적 한도에서 잘라낸다. 현재 게임의 패턴 삽입 경로와는 다르다. 다만 현재 패턴 생성기에서도 `RandomMarketGenerator`의 시드 생성 함수와 기업별 한도 정의는 사용한다.

| 수정할 내용 | 구현 위치 |
| --- | --- |
| 패턴 종류·기업별 가중치 | `PatternMarketGenerator.PickPattern` |
| 50/30/20 분기·제어점·훼손 방식 | `PatternMarketGenerator.Path` |
| 배치 구간·진폭·기울기·노이즈·축소·반올림 | `PatternMarketGenerator.Path` |
| 난수 초기화·기업별 스트림 | `PatternMarketGenerator.Generate`, `Inspect`, 내부 `Stream` |
| 기본 일일 한도·누적 한도·턴 배율 | `RandomMarketGenerator.BaseDailyLimitBps`, `AbsoluteCapBps`, `DailyLimitBps` |
| 기업 배열 순서 | `InvestmentRules.CompanyIds` |
| BANK 압축·BIO 이벤트 효과·추가 축소 | `MarketService.GenerateStockMarket` |
| BIO 확률·이벤트 판정 해시 | `MarketService.BioSuccessChance`, `StockHash` |
| 현재 게임 생성 진입점 | `DevTabletBootstrap`, `MarketService.CreateStockSystem` |
| 실험실 샘플·강제 비교 | `PatternLabWindow`, `PatternMarketGenerator.Inspect` |
| 화면에서 보이는 세로 범위 | `ChartVerticalRange`, `BarChartGraphic` |
