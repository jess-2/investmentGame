# 주식 투자 게임 최종 개발 정리

작성 기준: **2026-11-10 현재 코드와 검증 결과**. 최근 요청으로 변경한 규칙, 화면, 턴 전환 및 주식 초기화를 포함한다. 이전 문서의 주차별 거래·3초 공개 규칙과 충돌하면 이 문서의 현재 규칙을 기준으로 한다.

## 1. 게임의 현재 구성

4명이 제한된 정보를 구매하고 기업별 한정 주식을 확보한 뒤, 진입·청산 시점을 정해 6턴의 최종 자산을 겨루는 게임이다. 호스트가 TCP 서버와 규칙 판정을 담당하며 사람과 BOT이 같은 서버 명령을 사용한다.

| 항목 | 현재 적용 값 |
| --- | --- |
| 엔진 | Unity 6000.3.27f1 |
| 플레이 인원 | 4명 |
| 게임 길이 | 6턴, 턴마다 시장 30일 |
| 초기 자산 | 10,000 |
| 기업 | AI, SPACE, FOOD, BANK, BIO, AUTO |
| 일반 기업 공급 | 기업마다 전체 플레이어 합계 20주 |
| 개인 투자 규모 | 30칸 |
| 개인 기업별 한도 | 기본 10주, 집중 투자자 지정 기업 12주 |
| BANK 수용량 | 전체 120칸, 개인 30칸 |
| 매수 차례 | A→B→C→D를 2회, 차례마다 7초 |
| 차례당 신규 매수 한도 | 여러 기업 합계 15주 |
| 증강 선택 | 1·3·5턴, 최대 20초 |

현재 실행 경로는 `GameSettings.StockGame`과 `MarketService.CreateStockSystem(seed)`다. 기존 10턴·묶음 정보·아이템 등의 레거시 규칙과 검증용 fixture는 별도로 남아 있으므로, 해당 코드의 숫자를 현재 게임 규칙으로 해석하면 안 된다. 현재 연결 버전은 `prototype-v5-stock`, 규칙 버전은 `rules-v5-six-turn-shares`다.

## 2. 한 턴의 진행

```text
새 턴: 보유 주식·예약 초기화, 개인 30칸 BANK 시작
  → [1·3·5턴만] 증강 선택
  → 정보 탐색: 공용 정보 선택 → 개인 정보 구매·예약
  → A→B→C→D→A→B→C→D 매수
  → 진입·청산 구간 최종 결정
  → 1~30일 처리 및 전체 시장·BIO 이벤트 결과 공개
  → 정산·순위 → 다음 턴 / 6턴 종료 후 최종 결과
```

| 단계 | 기본 최대 시간 | 할 수 있는 일 |
| --- | --- | --- |
| 증강 선택 | 해당 턴에만 20초 | 제시된 후보 중 증강 선택 |
| 정보 탐색 | 60초 | 공용 정보 선택, 개인 정보 구매, 진입·청산 예약 |
| 주식 매수 | 7초 × 8차례 = 56초 | 자기 차례에 수량 변경·자동 주문 및 예약 편집 |
| 진입·청산 결정 | 23초 | 확보한 기업의 구간 최종 확인·확정 |
| 시장 공개 | 10초 | 전체 시장과 거래 결과 확인 |
| 결과 | 5초 | 자산·수익·순위 확인 |

정보 탐색의 60초에는 공용 정보 선택 시간이 포함된다. 공용 정보는 4명이 차례대로 기업의 5일 구간 하나씩 선택하며, 기본 설정에서 한 명당 최대 10초다. 공용 선택을 빨리 마치면 개인 탐색에 쓸 시간이 늘어난다. 같은 기업의 공용 구간은 서로 겹치지 않는다.

완료 조건이 충족되면 단계가 일찍 끝날 수 있다. 기본 최대 시간은 일반 턴 154초, 증강 턴 174초이며 대기실·일시정지 시간은 별도다.

**주차별 네 번 매수, 각 3초 시뮬레이션 및 중간 주가 공개는 현재 사용하지 않는다.** 두 매수 순환 사이에도 가격은 새로 공개되지 않는다. 최종 구간이 잠긴 뒤 서버가 30일을 처리하고 전체 시장을 한 번 공개한다.

### 자리와 플레이어 순서

A/B/C/D는 고정된 P1/P2/P3/P4가 아니라 해당 턴의 자리다. 자리는 턴마다 순환한다. 기본 매수 순서는 항상 `A→B→C→D→A→B→C→D`이며, 선점 투자자 증강을 사용하면 아직 진행하지 않은 차례 하나의 위치가 달라질 수 있다.

## 3. 주식 매수와 BANK

### 차례당 15주와 자동 주문

- 한 차례의 **새 매수량 증가분 합계**가 15주 이하여야 한다. 여러 기업에 나누어 투자할 수 있다.
- 예: 첫 차례 AI 10주 + SPACE 5주, 두 번째 차례 FOOD 10주 + AUTO 5주로 총 30주를 확보한다.
- 첫 차례에서 남긴 한도는 두 번째 차례에 더해지지 않는다. 같은 차례에 매도해도 이미 사용한 매수 한도는 복구되지 않는다.
- 기업 전체 공급 20주, 개인 기업 한도, 개인 총 30칸을 각각 검사한다. 주문은 전체 성공 또는 전체 실패이며 부분 체결하지 않는다.
- 잘못된 주문·공급 부족·같은 요청 재전송은 추가 매수 한도를 소모하지 않는다. 수량은 정수로만 받는다.
- 슬라이더를 움직이는 동안 선택 수량을 미리 보여 주고, **손을 놓으면 서버에 실제 주문**한다. 키보드 수량 변경도 자동 주문한다. 별도 거래 적용 버튼은 없다.
- 실제 매수 인정은 서버가 승인한 수량을 기준으로 한다. 실패하면 화면 수량을 서버 값으로 복구한다.
- 주문해도 7초가 연장되거나 차례가 자동 종료되지는 않는다. 완료 버튼을 누르면 조기 종료하고, 시간 만료 시 이미 승인된 주문을 유지한 채 다음 사람에게 넘어간다.
- 8차례 후의 진입·청산 결정 단계에서는 주식 수량을 바꿀 수 없다.

### BANK 자동 예금

다른 기업에 배정하지 않은 칸은 전부 BANK에 자동 예금한다. BANK를 직접 매수·매도하는 주문은 사용하지 않는다. 전원 미투자 시 `30칸 × 4명 = 120칸`을 BANK가 수용한다.

예약 진입 전, 투자 구간 사이, 최종 청산 후에도 해당 칸에는 BANK의 일별 수익률을 적용한다. 따라서 일부 기업만 사거나 아무 기업도 사지 않아도 30칸 전체의 운용이 이어진다.

## 4. 턴 변경 시 초기화와 유지 항목

최근 수정으로 **전 턴에 사고 팔지 않은 주식도 다음 턴에 자동 이월되지 않는다.** 완료된 턴의 결과 화면은 당시 상태를 보여 주고, 다음 턴 시작 시 초기화한다.

| 다음 턴 시작 시 초기화 | 다음 턴에도 유지 |
| --- | --- |
| 모든 일반 기업 보유·확보 수량 0주 | 정산된 자산과 누적 수익 |
| 개인 30칸 전부 BANK, BANK 전체 120칸 복귀 | 지난 턴 거래·수익·시장 이력 |
| 일반 기업마다 20주 공급 복구 | 선택한 증강과 사용 이력 |
| 진입·청산 예약, 잠금·완료 표시 | 연속 투자 판정용 과거 기록 |
| 슬롯 가치·일별 운용 기록·차례 매수 한도 | 다음 턴으로 넘기는 정보 할인 등 효과 |
| 이전 턴 개인뷰와 공개 차트 | 플레이어·방·자리 순환 정보 |

자산을 10,000으로 되돌리는 초기화가 아니다. 이전 턴 정산 자산을 가지고 새 포트폴리오를 구성한다. SPACE·장기 투자 증강의 연속 기록을 이어 가려면 해당 기업을 **매 턴 다시 매수**해야 하며 한 턴 쉬면 연속 기록이 끊긴다.

## 5. 정보 구매와 진입·청산 예약

### 정보 탐색

현재 정보 창 방식에서는 한 번의 정보 구매가 반드시 연속 5일이다. 같은 기업의 정보 창 사이에는 6~9일처럼 최소 4일의 미공개 공백이 있어야 하므로, 1~5일을 구매했다면 다음 구매는 10일차부터 가능하다. 1~5일과 6~10일을 연달아 구매해 미래를 전부 확인하는 방식은 허용하지 않는다. 코인은 1~5턴에 15개, 6턴에 25개를 지급하며, 이미 알고 있는 날을 제외한 신규 정보에 기본 1일당 1코인을 적용하고 증강 할인을 반영한다. 같은 턴 지급 요청을 다시 처리해도 중복 지급하지 않는다. 정보 코인은 투자 자산과 별도다.

공용 정보와 자신이 구매·획득한 개인 정보만 탐색 화면에 표시한다. 다른 사람의 개인 정보나 아직 공개되지 않은 미래 주가를 차트·축 값으로 노출하지 않는다.

### 예약 가능 시점과 적용

1. 공용 선택을 마친 정보 탐색 중에는 **아직 주식을 사지 않은 기업도 예약**할 수 있다.
2. 예약은 서버에 개인 초안으로 저장한다. 예약만으로 주식·공급·투자 칸을 선점하지 않는다.
3. 자기 매수 차례에도 예약을 편집할 수 있다. 다른 사람의 매수 차례에는 확정할 수 없다.
4. 이후 실제 확보한 기업에만 예약을 적용한다. 최종 결정 단계에서는 보유 기업의 구간을 검토한다.
5. 전원 확정 또는 시간 만료 시 서버가 예약을 잠근다. 이후 변경할 수 없다.

미설정 기업은 전체 기간 보유로 처리한다. 예약이 없어 끝까지 남은 주식도 다음 턴에는 초기화된다. 전량 BANK인 플레이어도 확정·시간 만료로 정상 진행한다.

### 거래 날짜와 차트

- 진입은 지정일 시가, 청산은 지정일 종가를 사용한다. 시가는 전날 종가다.
- 현재 주식 모드의 보유 기간은 **청산일 - 진입일 >= 7**이다. 따라서 1일 진입·7일 청산은 불가하고, 1일 진입·8일 청산부터 가능하다.
- 현재 주식 모드에서는 1~30일의 구간을 사용하며, 0일 기준 진입도 지원한다.
- 겹치지 않는 복수 구간을 설정할 수 있다. 앞 구간 청산일과 다음 진입일이 같은 중복 구간은 허용하지 않는다.
- 현재 주식 모드에는 레거시의 최소 5일·최대 10일 보유 규칙을 적용하지 않는다. 정보 구매 구간은 별도로 5일 고정·4일 공백 규칙을 따른다.
- 매수 카드 차트 또는 확대 버튼으로 정보 구매 화면과 같은 큰 차트를 연다. 저장된 예약 구간은 작은 차트와 확대 차트 모두에 띠로 표시한다.

## 6. 주가 생성·이벤트·정산

### 현재 주가 생성

방 시드·턴·기업별 난수로 0~30일의 경로를 미리 생성한다. 저장값은 전날 대비 변화가 아니라 **0일 대비 누적 등락률(bps)**이다. 가격 기준은 `10000 + 누적 bps`이며 100bps는 1%포인트다. 각 턴의 0일은 다시 0으로 시작한다.

완성 50%·훼손 30%·비패턴 20% 분기와 기업별 패턴 가중치를 사용한다. 박스권·M자·W자·깃발형에 시간 배치·기울기·노이즈를 섞고 기업별 범위·일일 한도를 보정한다. 생성 분기의 확률은 수익 보장이나 눈으로 패턴을 맞힐 확률이 아니다.

- BANK: 생성값을 `int(200 × tanh(v / 2500))`로 압축한다. 수식의 이론적 범위는 ±200bps지만 실제 입력 제한으로 변동폭은 더 작다.
- BIO: 시드·턴으로 35~75%의 성공 확률과 성공 여부를 정한다. 성공 +1800bps 또는 실패 -1600bps 효과를 13~30일에 걸쳐 누적한 뒤 범위를 다시 보정한다.
- BIO 결과는 플레이어 확정 후 새로 추첨하는 것이 아니라 시장 생성 시 고정되고 마지막 시장 공개에서 확인한다. 바이오 연구원은 실제 확률을 개인에게 알려 준다.
- 플레이어의 매수·매도·정보 구매량으로 가격이 바뀌지는 않는다. 별도로 구상한 신규 공통 시장 뉴스·이벤트 시스템은 이번 변경에 추가하지 않았다.
- 패턴 실험실은 기본 생성기를 다루며 실제 게임의 BANK·BIO 후처리 결과와 완전히 같지는 않다.

확률·기업별 범위·패턴 구성의 자세한 내용은 [주가 생성.md](./주가%20생성.md)에 정리했다.

### 정산 방식

30칸을 각각 정규화된 운용 단위로 두고, 날짜별 기업/BANK 수익률을 반영한다. 예약 구간 밖에서는 BANK를 적용한다. 누적 슬롯 손익에 해당 턴 투자 가능 자산의 1/30을 곱하고 증강 효과와 반올림을 반영해 최종 자산을 계산한다. 각 턴 정산과 지난 시장·투자 이력은 다음 턴에도 보존한다.

## 7. 증강 구현 현황

**증강은 선택 화면만 있는 상태가 아니다. 아래 효과가 서버에 연결되어 있다.** 다만 예약 전량 청산과 연속 투자·분산 판정 사이에는 보완할 조건이 남아 있다. 식별자는 12종이며 `FLEXIBLE`을 제외한 11종이 새 후보 대상이다.

| 증강 / 식별자 | 현재 구현 | 한계·주의 |
| --- | --- | --- |
| 선점 투자자 / PRIORITY | 게임당 1회, 미래 자기 매수 차례를 한 자리 앞당김 | 진행 중이거나 완료된 차례를 앞지를 수 없음 |
| 유연한 투자자 / FLEXIBLE | 여러 기업 주문을 모든 플레이어의 기본 규칙으로 통합 | 새 후보에서 제외, 식별자는 호환을 위해 유지 |
| 기회 포착 / OPPORTUNITY | 유효한 주문이 공급 부족으로 실패하면 턴당 1회 다음 턴 정보 할인 2일 | 수량·개인 한도 등이 잘못된 주문은 대상 아님 |
| 내부 분석가 / ANALYST | 선택 즉시 할인 2일, 이후 매 턴 정보 할인 2일 | ‘다음 턴부터’라는 설명과 선택 턴 적용이 불일치 |
| 추세 추종 / TREND | 직전 턴 마지막 3일 연속 상승 기업의 이번 턴 1~3일 정보 추가 | 개인 정보 효과이며 가격 자체를 바꾸지 않음 |
| 바이오 연구원 / BIO_RESEARCH | 실제 BIO 연구 성공 확률 표시 | 성공 여부·가격을 변경하지 않음 |
| 우주 개척자 / SPACE_PIONEER | SPACE 연속 투자 2턴부터 해당 기업 수익률 +2%p | 매 턴 재매수 필요, 예약 전량 청산 시 연속 기록이 끊겨 보너스 적용에 한계 |
| 복리의 마법 / CASH_INTEREST | 시간 가중 BANK 예금에 +2%, 전체 투자 가능 자산 +1% 상한 | 실제 BANK 운용 시간을 사용 |
| 위험 분산 / DIVERSIFY | 3개 이상 기업을 각각 3주 이상 보유한 조건에서 손실 20% 완화 | 정산 시 잔여 수량 판정, 예약 청산 후·날짜별 보유 조건은 미완성 |
| 장기 투자의 힘 / LONG_TERM | 같은 기업 연속 투자 3턴부터 해당 기업 수익률 +2%p | 매 턴 재매수 필요, 예약 전량 청산 시 연속 기록이 끊겨 보너스 적용에 한계 |
| 하락장 사냥꾼 / CONTRARIAN | 직전 턴 하락 기업의 이번 턴 1~3일 정보 추가 | 개인 정보에만 추가 |
| 집중 투자자 / CONCENTRATION | 선택한 일반 기업의 개인 한도를 10주→12주로 변경 | 기업 총 20주·차례당 15주·개인 총 30칸은 유지 |

## 8. 최근 화면 및 진행 오류 수정

### 매수·예약 화면

- 정보 탐색에서 예약 버튼을 사용할 수 있도록 서버 권한과 화면 조건을 연결했다.
- 매수 카드 차트는 카드 전체 폭을 사용하고 확대 차트를 제공한다. 두 차트에 예약 구간을 표시한다.
- 회색 네모는 기업의 남은 물량, 플레이어 색은 확보한 물량을 나타낸다. 다른 플레이어의 확보 칸도 구분한다.
- 수량 컨트롤 아래의 중복 비율 설명과 하단 금색 포트폴리오 네모를 제거했다.
- 차례 표시를 위로 옮기고 P1/P2/P3/P4 글자를 키웠다. 현재 순번을 강조한다.
- 매수 중에는 오른쪽 중복 완료·증강 고정 카드를 접어 투자 영역을 넓힌다. 증강은 상단 내 증강에서 확인한다.
- 서버 응답 때 수량 컨트롤을 계속 새로 만들지 않아 드래그 중 입력이 끊기는 문제를 줄였다.

### 다음 턴 타이머·화면·버튼 복구

턴 번호만 바뀌고 시간·버튼이 이전 턴에 남는 문제에 대응했다.

- 새 턴에서 이전 개인뷰·대기 주문·잠금·완료·예약·공개 차트 상태를 정리한다.
- 이번 턴 공용 상태와 이전 턴 개인뷰를 섞어 버튼을 활성화하지 않는다. 늦게 온 과거 메시지도 현재 화면을 되돌리지 못한다.
- 서버가 0.5초마다 현재 시간과 마감을 공지한다. 공지로 단계 시간이 연장되거나 재시작되지 않는다.
- 개인뷰 재조회는 최신 공용 상태와 요청자 자신의 개인 정보만 반환한다.
- 화면은 프레임에서도 상태 참조 변경을 확인해 갱신 알림 누락을 복구한다. 새 턴 개인뷰가 늦으면 재조회를 요청한다.
- 정보 구매→주식 매수→진입·청산→정산을 실제 시간 기준으로 6턴 연속 진행하는 회귀 검증을 추가했다.

## 10. 실행과 검증

1. Unity Hub에서 이 프로젝트를 **6000.3.27f1**로 연다.

## 11. 남아 있는 보완·검증 범위

1. **증강 판정:** 위험 분산은 정산 잔여 수량 대신 날짜별 실제 보유를 기준으로 할지 확정·구현해야 한다. SPACE·장기 투자도 예약 전량 청산 시 연속 기록과 보너스 판정을 보완해야 한다.
2. **설명 일치:** 내부 분석가의 선택 턴 할인과 ‘다음 턴부터’ 설명을 맞춰야 한다. 일부 증강 화면의 선택 시점 문구도 실제 정보 탐색 전 진행과 맞춰야 한다.
3. **추가 이벤트:** 현재 BIO 연구 이벤트 외 신규 공통 시장 이벤트는 계획 단계다. 기존 레거시 아이템·경매·능력 전체가 현재 주식 모드에서 제공되는 것은 아니다.
4. **실기기 검증:** 4대의 실제 PC/LAN, 독립 실행 빌드의 전체 플레이 및 모든 증강 조합은 이번 자동 검증으로 확인하지 않았다. Unity 검증은 EditMode UI 회귀이며 배포 빌드 전체 검증을 뜻하지 않는다.

이 문서는 현재 상태를 인수인계하는 기준이다. 이후 규칙을 변경하면 코드 상수·서버 검증·화면 설명·이 문서를 함께 갱신한다. 기존 기획 및 변경 이력은 [stock_game_system_design.md](./stock_game_system_design.md)에 보존한다.
