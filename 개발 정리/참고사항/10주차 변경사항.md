| 화면 | 변경 내용 |

미리보기용 능력·아이템 ID와 서버 ID의 차이를 표시 모델에서 변환하도록 정리했다. 상점·보유 아이템의 미지원 동작에는 실행 불가 사유를 표시한다.

## 2. 기업 그래프 확대·축소 및 확대 상태 정보 구매

### 확대·축소

1. 정보 구매 창에서 자세히 볼 기업의 **확대하기**를 누른다.
2. 해당 기업의 그래프가 태블릿 중앙에 크게 열린다.
3. **축소하기**를 누르면 기존의 6개 기업 그래프로 돌아간다.

확대 화면은 기업 카드나 페이지 마스크에 잘리지 않도록 배치했다. 턴·단계가 바뀌면 확대 화면을 닫으며, 확대 중에도 새로 받은 정보를 반영한다.

### 확대 상태에서 정보 구매

- 확대 그래프 하단에서 해당 기업의 정보 6묶음을 바로 구매한다.
- 보유 코인과 무료 정보 횟수, 열람 중·구매 완료·요청 중 상태를 표시한다.
- 응답 대기 중인 묶음은 다시 구매할 수 없다. 코인과 무료 정보가 모두 없거나 정보 탐색 단계가 아니면 구매를 막는다.
- 코인이 0개여도 무료 정보 횟수가 남아 있으면 사용할 수 있다.
- 서버 응답이 오면 확대 상태를 유지한 채 그래프와 잔액을 갱신한다. 응답 전에 코인을 임의로 차감하지 않는다.

작은 카드와 확대 화면은 같은 구매 상태 판정 코드를 사용한다. 구매하지 않은 구간의 실제 주가나 수익률은 공개하지 않는다.

## 3. 기업 찜·우선순위 및 개인 투자 계획

### 기업 찜과 순위

- 확대 화면에서 기업을 **찜하기**하고 **1~6순위**를 지정할 수 있다.
- 순위를 지정하면 해당 기업을 찜한 상태로 표시한다.
- 이미 다른 기업이 사용 중인 순위를 지정하면 두 기업의 순위를 맞바꾼다. **미정**으로 순위를 해제할 수 있다.
- 찜과 순위는 본인만 보는 메모이며, 기업의 투자 자리를 예약하거나 서버에 기업 선택 명령을 보내는 기능은 아니다.

### 진입·청산 구간 저장

1. 정보 탐색 또는 기업 선택 단계에서 그래프를 확대한다.
2. 그래프에서 **진입일 → 청산일** 순서로 클릭한다.
3. 저장한 구간을 음영과 진입·청산 표시로 확인한다.
4. 우클릭 또는 **진입 후보 취소**로 미완성 후보를 취소하고, **삭제**로 저장한 구간을 지운다.

기존 투자 주문과 같은 규칙을 적용한다.

- 날짜 범위: 0~30일
- 보유 기간: 5~10일
- 기업별 최대 2구간
- 구간 중복 불가. 앞 구간의 청산일과 다음 구간의 진입일이 같은 것은 허용
- 미열람 날짜에도 계획을 잡을 수 있지만, 모르는 주가와 수익률은 추정해서 표시하지 않음

### 이후 게임 화면과의 연결

| 단계 | 표시·동작 |
| --- | --- |
| 정보 탐색 | 기업 카드와 확대 그래프에서 찜·순위·계획을 확인하고 편집한다. |
| 투자 자리 경쟁·기업 선택 | 기업별 찜·순위·계획 구간을 확인하며 실제 투자할 기업을 고른다. |
| 투자 주문 | 선택한 두 기업의 계획을 주문 초안에 복사한다. 구간과 비율을 수정한 뒤 **주문 확정**으로 실제 제출한다. |
| 주문 확정 이후·전체 시장 공개 | 실제 확정된 본인 주문의 진입·청산 구간을 표시한다. 투자 화면에서 구간을 수정했다면 이전 개인 계획 대신 수정한 주문을 표시한다. |

선택하지 않은 기업의 개인 계획을 확정 주문처럼 표시하지 않는다. 개인 계획은 같은 턴의 화면 전환 동안 유지되고 다음 턴에 초기화된다. 파일 저장과 새 클라이언트에서의 복원은 지원하지 않는다.

## 4. 단계 안내 문구 밀림 수정

빠르게 단계를 진행했을 때 이전 단계의 안내가 대기열에 남아 나중 화면에 나타나던 현상을 수정했다.

- 턴·단계가 바뀌면 표시 중인 안내와 대기 알림을 즉시 지운다.
- 기업 선택 차례가 다음 참가자로 넘어가면 지난 차례의 안내를 지운다.
- 정보 구매·주문 확정·자동 선택 안내는 관련 단계에서만 표시한다.
- 정산 데이터가 결과 단계보다 먼저 도착해도 결과 단계에 들어간 뒤 안내한다.
- 다음 턴으로 넘어가면 이전 턴의 정산 안내가 남지 않는다.
- 연결 종료 시에는 대기 중인 과거 안내를 지우고 종료 사유를 표시한다.

## 5. 실제 게임 일시정지·재개

### 게임 내 버튼

방장은 게임 중 왼쪽 위 **일시정지** 버튼을 누른다. 모든 참가자에게 정지 화면을 표시하고 다음 항목을 멈춘다.

- 서버의 게임 경과 시간
- 단계 마감 및 기업 선택 마감 시간
- BOT의 게임 행동
- 구매·기업 선택·투자 확정·단계 완료 등 서버 상태를 바꾸는 게임 명령

중앙 또는 왼쪽 위 **게임 재개**를 누르면 남아 있던 시간부터 이어서 진행한다. 정지 중 흘러간 실제 시간을 재개 시 한꺼번에 적용하지 않는다. 정지 전의 기업 선택 후보와 투자 주문 초안도 유지한다.

정지·재개 권한은 방장에게만 있다. 대기실과 게임 종료 이후에는 버튼을 사용할 수 없다. 서버는 정지 중 직접 도착한 게임 명령도 거절한다.

### Unity Editor 버튼과의 차이

| 버튼·상황 | 동작 |
| --- | --- |
| 방장 게임 화면의 일시정지 | 모든 참가자의 게임 진행과 타이머를 정지한다. |
| 방장 Editor의 Pause(Ⅱ) | 같은 서버 정지 기능에 연결한다. Pause 해제 후 멈춘 시간을 제외하고 진행한다. |
| 게임 버튼으로 정지한 뒤 Editor Pause 해제 | 게임 내 정지 상태를 유지한다. 게임 재개 버튼으로 별도 재개한다. |
| 참가자 Editor만 Pause | 방장의 서버는 계속 진행한다. 전체 정지는 방장이 해야 한다. |
| Editor의 Stop(■) | Play 모드와 해당 방을 종료한다. 이어서 플레이하려면 Pause 또는 게임 내 정지를 사용한다. |

기존 현상은 Unity 화면 갱신이 멈춰도 서버의 실제 시계가 계속 흐르기 때문에 발생했다. 서버 경과 시간에서 정지 기간을 제외하고 `PublicState.paused`를 모든 참가자에게 전달하도록 보완했다. 정지 제어는 호스트의 로컬 서버 API로 제공하며 원격 참가자용 정지 명령은 추가하지 않았다.

## 6. 통합 오류 및 실행 경로 보완

- UI와 BOT 영역에 이름이 같은 난이도 타입이 있어 발생하던 컴파일 충돌을 명시적 타입 별칭으로 정리했다.
- 실제 게임 호스트가 B의 `MarketService.CreateRandom`을 사용하도록 연결했다. 새 게임의 시드는 `RandomMarketGenerator.NewSeed()`에서 생성한다.
- D 선택 흐름 테스트의 서버 설정을 테스트 대역에 맞는 `GameSettings.Fixture`로 명시하고, 초기화 실패 시 테스트 종료 처리에서 추가 오류가 발생하지 않도록 했다.
- 실제 화면 표시 모델과 개인 투자 계획을 .NET 검증 대상에도 포함했다.
- Unity 씬 저장에 따른 오브젝트 식별자·직렬화 순서 변경은 유지했다. 해당 변경을 새로운 게임 규칙으로 분류하지 않았다.
