# 전체적인 흐름

## 협의된 사항들


- 앞으로 구글 미팅으로 논의할텐데 시간 정하기
    - 일요일 13시 혹은 금요일 18시
- 화요일 발표 후에는 20분정도 다음을 얘기함
    - 개발하는데 애로 사항 및 오류들
    - 협의할 것들
    - 개발하면서 궁금한 점들
    - 피드백을 받은 뒤 추가적인 건의사항
- Google Meeting 때는 다음을 얘기함
    - 자신이 한 주 동안 구현한 것들. 이떄 어떤 기능이 추가됫으며 어떻게 동작하는지 자세히 설명
    - 추가적인 협조 요청 혹은 건의사항
    - 파일 병합 시 발생하는 오류들 조정


## 파일 설명
- 각 개발자들은 자신의 AI모델에게 7가지 파일을 주어야 한다.
- 아래 4가지는 공통적으로 사용하는 파일이다.
    - 00공통 맥락
    - 공통 연결 규약
    - 결정 사항 (`02_결정_사항.md`) : 사용자가 직접 정했거나 AI에 위임하여 정한 초기 규칙의 확정 기록
        - 구현 후 밸런싱할 때 다시 고려할 사항들
    - Github_병합_지침 : AI가 github 병합할 때 고려할 지침
- 아래 3가지는 각 개발자마다 개별로 사용하는 파일이다.
    - 임시데이터.json : 다른 담당자의 구현을 기다리지 않고 테스트할 떄 사용하는 입력 데이터
    - 작업 지침.md : 구현할 기능, 담당 범위, 구현 순서, 다른 개발자에게 주거나 받아야 할 것들이 명시됨
    - 통과 기준.json : 기대 결과와 실제 연결 후 확인해야할 항목

## 기능의 흐름
- 각 담당 분야의 핵심 로직은 해당 담당자가 구현한 기능이다.
    - 예를 들어 정보를 산 후 코인을 차감하는 기능은 C가 구현하고 이를 A와 D가 사용한다.
    - 진입과 청산을 결정하는 기능은 B가 구현하고 이를 A와 D가 사용한다.
- 요청과 결과 흐름을 기능별로 구분하면 다음과 같이 이뤄진다.
```
D: 구매 버튼 클릭 → 구매 요청 생성
        ↓ 네트워크 메시지
A: 요청자·턴·단계 확인 → C의 구매 함수 호출
        ↓ 서버 내부 함수 호출
C: B에서 정보 조회 → 코인 차감·구매 기록 → 결과 반환
        ↓ 서버 내부 함수 반환
A: 구매자에게 결과 전송
        ↓ 네트워크 메시지
D: 잔액과 그래프 갱신

```

- 플레이어 흐름은 다음과 같다.
```
P1·P2·P3의 화면(D)
    → P0의 서버(A)
    → P0에서 실행되는 규칙(B/C)
    → 요청자에게 결과 전송
```

## Github 흐름
- 원본 저장소에서 clone을 한 후 기능 branch를 만든다.
    - 이때 `feature/`와 같은 접두사로 시작해야 한다.
- 이후 원본 저장소의 `dev` 브랜치로 PR을 보낸다.


## 복사해서 사용할 시작 프롬프트


```text
나는 투자 게임의 [A/B/C/D] 담당 개발자다.
이번 작업은 이 프롬프트 아래에 붙인 팀장의 카카오톡 업무 지시를 기준으로 진행해라.
업무 지시에서 구현할 기능과 범위를 파악하고, 명시되지 않은 다른 기능까지 임의로 확장하지 마라.
개발 프로세스를 읽어 전체 게임 흐름과 담당자 간 연결을 이해해라.
공통 맥락, 연결 규약, 규칙 확정 기록, GitHub 지침과 내 역할의 작업지침·임시데이터·통과기준을 읽어라.
현재 저장소의 실제 Unity 버전·패키지·공통 DTO·인터페이스·현재 브랜치·기존 변경을 먼저 확인해라.
개발 기준 브랜치는 dev다. 기존 작업을 보존하고 최신 dev를 기준으로 기능 브랜치에서 작업해라.
내 담당 범위에서 구현하고, 다른 담당자의 규칙을 복제하거나 공통 DTO를 임의로 바꾸지 마라.
공통 기반이 없으면 필요한 계약을 먼저 구체적으로 제안하고, 승인된 공통 기반과 맞는 임시 구현을 사용해라.
게임 규칙은 rules-v2를 따르고, fixture의 고정 주가·고정 순서·수동 타이머는 테스트용 설정으로 구분해라.
입력 데이터를 실제 구현에 넣은 결과를 통과기준과 비교해라. 기대값을 구현에 맞춰 고치지 마라.
전체 흐름에서 호출 순서·상태 변경 책임·개인 정보 공개 범위가 맞는지도 확인해라.
변경 파일, 입력·출력 변경, 실행한 검증과 결과, 미실행 검증, 남은 연결 지점을 보고해라.
커밋·푸시·PR 생성은 이번 업무 지시에서 허용한 범위만 수행해라. PR 대상은 dev이며 병합은 관리자 또는 지정 담당자에게 맡겨라.
```
