# 모든 AI에 제공할 공통 맥락

2026-11-02 갱신: 실제 기본 기능은 [04 현황](./04_현재_구현_현황.md), 다음 작업은 [05 계획](./05_다음_구현_계획.md)을 먼저 읽는다. 아래 rules-v2/fixture 수치는 기존 회귀 기준이다. 다음 플레이 INFO는 **90초**, 일반턴 최대 **160초**를 적용할 예정이며 현재 코드는50초다. 기존 fixture를 새 기능 기대값으로 일괄 변경하지 않는다.

## 게임의 목적과 구조

- 블랙웨일 증권이 개최한 비밀 투자대회다. 빚이 있는 참가자들이 경쟁하며 최종 승자에게 빚 탕감과 보상이 주어진다. 최신 7주차 정리의 세계관을 따른다. PPT의 데스게임 묘사를 새 기능·사망 처리로 확대하지 않는다.
- 목표 게임은 4명·10턴, 한 턴의 가상 시간은30일이다. 기존 기본턴은 최대120초였고 다음 개선은 INFO90초를 포함해 최대160초다. 실제 연결 구현은 현재1턴이다.
- 각자 정보를 해석·구매하고 기업 선택 자리를 경쟁한 뒤, 진입·청산을 사전 확정한다. 시장 공개 후 수익을 정산한다. 실시간 매매 게임이 아니다.
- Unity에서 방장 1명이 서버와 플레이어를 함께 맡고 나머지 3명은 참가자로 접속한다. 방장도 일반 플레이어와 같은 규칙과 정보 표시를 적용받는다.
- 초기 검증은 고정 데이터로 한 턴, 이후 3턴·10턴으로 확장한다. 기능을 확장하기 전 수동/고정 데이터 모드와 실제 모드를 구분한다.

## 역할의 의미

| 표기 | 의미 |
|---|---|
| 개발자 A/B/C/D | 각각 멀티·진행 / 시장·투자·정산 / 정보·코인·효과 / UI·그래프 담당 |
| P1/P2/P3/P4 | 테스트 게임 참가자. P1이 방장 |
| 선택 자리 A/B/C/D | 기업 선택 우선순위. 개발자 역할과 별개 |

Unity 프로젝트와 Shared DTO는 이미 존재한다. 실제 코드·Unity 버전·패키지를 먼저 확인하고 같은 계약을 재사용한다. 아래 과거 제안 이름보다 현재 코드를 우선한다. 다른 담당자의 파일이나 사용자의 미완성 작업을 덮어쓰지 않는다.

## 자료를 해석하는 기준

1. 이후 팀이 명시적으로 확정한 변경이 있으면 본 패키지와 같이 갱신한다.
2. 프로토타입 구현 범위와 공통 데이터는 본 패키지 및 기존 fixture의 동결된 형식을 사용한다.
3. 원문 충돌은 [규칙 확정 기록](./02_결정_사항.md)의 rules-v2로 해결했다. 각 AI가 이전 발표의 배율이나 날짜 제한을 다시 선택하지 않는다.
4. 원문에 필수로 적힌 후순위 기능을 삭제한 것으로 해석하지 않는다. 2주 시제품에서 구현을 유예한 것이다.
5. 고정 데이터·수동 재생은 테스트 모드로 구분한다. 기능의 규칙이 확정되어도 기본 시제품에 아직 구현하지 않은 효과는 후속 작업으로 분리한다.

위 차주 목표는 사용자 추가 요청으로 이전 유예 범위를 변경한 것이다. 기본1턴 fixture는 회귀로 보존하고 실제 차주 계획은 [07 통합 요약](./07_현재_구현_및_차주_계획.md)을 따른다. 입찰턴 시간은 INFO90초+입찰15초를 포함한 최대175초 기본안이다.

## 기업·투자·정보 규칙

| 기업 ID | 변동성 |
|---|---|
| AI | 높음 |
| SPACE | 높음 |
| FOOD | 낮음 |
| BANK | 낮음 |
| BIO | 극단적 |
| AUTO | 중간 |

- 매 턴 서로 다른 기업 2개에 반드시 투자하며 한 기업에는 최대 2명까지 투자한다.
- 투자 비율은 5:5·6:4·7:3 중 하나다. 요청의 기업 배열 순서와 비중은 별도 의미이므로 임의 정렬하지 않는다.
- 한 턴 기업 선택은 자리 순서 A→B→C→D→D→C→B→A다. 1~8턴은 자리를 순환하고 9~10턴은 입찰과 연결되지만, 이번 기본 fixture는 1턴만 검증한다.
- 기업별 진입·청산 구간은 사전에 확정하며 1~2개다. 날짜는 0~30일의 정수로 일별 선택, 보유기간은 청산일-진입일 기준5~10일이다. 3→8·3→13일 허용, 3→7·3→14일 거절. 겹침 금지, 앞 청산일=다음 진입일 허용.
- 기업마다 정보 6묶음, 한 묶음은 5일치의 일별 값이다. 0일차 대비 변화율이며 전일 대비 수익률이 아니다.
- 기업마다 2묶음을 전원에게 동일하게 무료 공개한다. 고정 테스트에서는 위치도 고정한다. 실제 난수 모드에서는 서버가 한 번 선택한다.
- 코인 1개로 정보 1묶음을 구매하며 코인은 이월 가능하다. 턴당 지급량 3개·5개는 구매 횟수 상한과 다르다.
- 전체 36묶음·180개 일별 값 중 무료 공개는 12묶음·60개 값이다. 0일차 기준값 6개는 이 180개에 포함하지 않는다.
- 순위는 총자산 기준. 타인의 투자 기업·금액·구간 명단은 직접 표시하지 않는다. 차례·잔석으로 선택을 추론하는 것은 허용된 심리전이다.

## 단위와 자료형

- 비율은 정수 bps. `100 bps = 1%`, `-4000 = -40%`, `3000 = +30%`. UI에서는 100으로 나누어 `%` 표시.
- 비중은 `weightBps`. `6000`은 60%, 두 기업 합은 `10000`.
- 자산·손익은 정수 금액, 곱셈 중간값을 포함해 C#의 `long` 등 범위를 확보한다. 코인과 날짜는 정수.
- 서버 주가 배열은 31개이며 인덱스가 0~30일이다. `dailyChangesBps[0] = 0`.
- 개인 화면의 묶음 배열은 5개 값이며 첫 날짜는 `startDay`다. 화면 배열 인덱스를 월 날짜와 혼동하지 않는다.
- 미열람은 값 없음이다. 0%와 구분하고, 서버 원본을 UI에서 숨김만 처리하는 설계로 만들지 않는다.
- 공통 DTO는 단일 구현을 사용한다. 필드명·대소문자·단위·enum 문자열을 각 AI가 다르게 만들지 않는다.

## 확정된 기본 규칙과 테스트 모드

아래는 [00_rules.json](../임시%20데이터%20및%20검증용/00_rules.json)의 rules-v2 설정이다. 고정 주가·고정 공개위치·P1~P4 초기순서와 수동 재생만 fixture 전용이다. 전체 입찰·아이템·능력·재접속·타임아웃은 02의 확정 기록을 따른다.

- 초기 자산 10,000, 1턴 INFO 시작 코인 3개. 이 3개는 이미 지급되었다.
- 6턴부터 지급량 5개로 증가. 코인 이월과 같은 턴 중복 지급 방지를 확인한다.
- 날짜는 정수 0~30일, 보유기간 5~10일, 기업당 1~2개 비중복 구간. 청산일과 다음 진입일이 같은 것은 허용.
- 2개 구간은 같은 배정 원금을 다시 사용하고 구간 수익률을 합산한다. 중간 이익 재투자 없음.
- 배정 원금과 기업 손익은 각각 0 방향 버림. 음수에서 내림과 다름에 주의.
- 공개/구매 정보 재구매는 `ALREADY_VISIBLE`, 추가 차감 없음.
- 기업 최종 손실률은 최저-100%, 공격 후 자산은 최저0. 자산0은 탈락하지 않고 다음턴1,000 지원. 기본1턴 fixture에서는 발생하지 않는다.
- 턴 중 자산 동점은 공동 순위, 표시 순서만 ID. 최종 승자는 자산→코인→최고 단일턴 수익률→시작 공개 추첨순번으로 결정.
- 일반턴 INFO50초·선택32초·주문23초·공개10초·결과5초. 3·6·9턴은 INFO를35초로 줄여 입찰15초를 포함. 최대120초다.
- 시간 초과 기업은 BANK→FOOD→AUTO→AI→SPACE→BIO 중 가능한 첫 기업, 미제출 주문은50:50·각0→5일. 실제 접수는 서버 수신시각이 마감보다 빨라야 한다.
- fixture 타이머 `MANUAL_FOR_FIXTURE`는 재현용 일시정지 모드이며 실제 타이머·자동선택 미결정이라는 뜻이 아니다.

정산은 실제 주가 비율이 아닌 게임의 변화율 차이 공식을 사용한다.

```text
투자 가능 자금 I = 턴 시작 자산 S - 해당 턴 구매/입찰 비용
첫 기업 원금 = trunc(I × 첫 기업 weightBps / 10000)
둘째 기업 원금 = I - 첫 기업 원금
구간 수익률 bps = 청산일 변화율 bps - 진입일 변화율 bps
기업 손익 = trunc(배정 원금 × 각 구간 수익률 bps 합 / 10000)
기업 최종 수익률은 효과 적용 후 최저 -100%로 제한
최종 자산 = max(0, I + 두 기업 손익 - 실제 감산 + 효과 수입)
```

AI 10일차 -40% → 15일차 +30%는 구간 +70%다. P1 전체 포트폴리오 수익률은 +42.8%이므로 둘을 구분한다.

## 서버 권한과 비공개 데이터

- 구매·선택·주문·정산은 서버에서 확정한다. 클라이언트는 의도와 필요한 입력만 보낸다.
- 방장 자신의 UI도 동일한 요청/응답 경로와 개인 필터 데이터를 사용한다.
- 비공개 원본을 모든 플레이어에게 동기화하고 화면에서만 가리지 않는다. 개인 정보·주문은 대상에게만 보낸다.
- 방장 PC에는 원본이 존재한다. 정상 화면에서 숨기는 것과 변조된 호스트로부터 원본을 보호하는 것을 혼동하지 않는다.
- 개발 테스트 파일과 통과기준은 정식 클라이언트 빌드에 통째로 넣지 않는다. 개발자가 열람하는 정답 데이터는 실제 플레이어에게 전달할 데이터가 아니다.
