# C와 A·D 연결 기록

후속 B 통합·턴 기록 보존은 [B 통합 기록](../B/통합_및_검증.md)을 따른다.
아래 B 대역·초기 검증 개수 설명은 최초 C 연결 당시의 기록이다.

작성일: 2026-11-02. 기준: `prototype-v2` / `rules-v2`, Unity `6000.3.27f1`.

## 연결 구조

`SharedInformationService`가 공통 `IInformationService`를 구현하고 C의 기존
`InvestmentGame.Rules.Information.InformationService`를 호출한다.
네트워크에는 Shared DTO만 전달하며 C의 내부 모델을 별도 통신 DTO로 사용하지 않는다.

- B → C: 공통 `IMarketDataSource`를 C의 `IMarketInformationReader`로 변환한다.
  시장 생성·공개 위치 선택은 B의 책임이다. 누락되거나 길이가 잘못된 묶음은 구매 실패로 처리한다.
- A → C: `GrantTurnCoins`에서 방별 상태와 참가자를 초기화하고 턴 지급 원장으로 중복 지급을 막는다.
  구매·개인뷰에는 A가 확인한 신원을 사용한다.
- C → D: 공개/본인 구매 정보와 코인에 B의 본인 자산·선택 기업·주문을 조합해 공통 `PlayerView`를 반환한다.
  배열은 복사하고 타인 구매 내역은 포함하지 않는다.

서비스는 `BlackWhale.Information` 어셈블리로 분리했다.
C 테스트도 Editor 전용 테스트 어셈블리에 분리하여 일반 플레이어 어셈블리에 들어가지 않게 했다.
공통 DTO·인터페이스·기존 `.meta` GUID는 변경하지 않았다.

## 실행 방법

D 개발용 Scene의 `DevTabletBootstrap`은 기존 `DevInformationService`를 계속 사용하지만,
이 클래스는 이제 실제 C 서비스를 감싼 개발용 오류 주입 래퍼다. 코인/구매 규칙을 복제하지 않는다.
`ForceNextBuyError`는 개발 화면과 실패 안내 테스트용으로만 유지한다.

Unity 메뉴 `BlackWhale → D 개발용 태블릿 UI 씬 만들기`로 Scene을 열고 Play한다.
현재 구성은 A의 실제 진행 + C의 실제 정보/코인 + D UI + B 대역 + 봇 3명이다.
기존 사용자가 만든 Scene 파일은 이 변경에서 수정하지 않는다.

실제 TCP 호스트에서는 같은 B 인스턴스를 두 서비스에 전달한다.

```csharp
var information = new BlackWhale.Rules.Information.SharedInformationService(actualMarket);
await networkSession.Host(actualMarket, information, displayName, allowLan: true);
```

## 수정한 문제

- C 요청 캐시 키에 턴을 포함한다. 방 분리는 어댑터의 방별 C 인스턴스가 담당한다.
  같은 턴의 다른 내용은 `REQUEST_ID_CONFLICT`, 동일 내용은 원응답을 반환한다.
- 개인뷰의 무료/구매 묶음을 합친 뒤 묶음 번호로 정렬한다.
- 참가자 등록·초기 코인 0 → 첫 턴 지급 3개를 A의 턴 시작 호출에 연결한다.
- D에 필요한 수신자·단계·자산·본인 선택 기업·주문을 공통 형식으로 조합한다.
- 시장 조회 실패는 payload 없이 `MARKET_UNAVAILABLE`로 전달하고 D 안내 문구를 추가한다.
