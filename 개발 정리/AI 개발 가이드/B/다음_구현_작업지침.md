# B 다음 구현: 입력 개선 회귀·BOT 주문·시장 공급자

[현재 현황](../04_현재_구현_현황.md), [다음 계획](../05_다음_구현_계획.md), [검증](../06_다음_구현_검증.md), 공통 00~03과 Shared를 먼저 읽는다. 현재 `MarketService`는 실제 선택/주문/정산 서비스이므로 대역을 새로 만들지 않는다.

## NEXT-B01: 마우스/BOT 입력에 기존 서버 규칙 적용

이번 UI/BOT 개선 때문에 손익 공식을 바꿀 필요는 없다. D와 A가 만드는 주문을 실제 `OrderValidator`와 `MarketService`에 넣고 다음을 확인한다.

| 입력 | 기대 |
|---|---|
| 3→8, 3→13, 25→30 | 허용 |
| 3→7, 3→14, 26→31, 소수 날짜 | 거절·무변경 |
| [0→5, 5→10] | 접점 같음 허용 |
| [0→10, 5→15], 3개 구간, 기업당 빈 구간 | 겹침/초과/누락 거절 |
| 선택 기업 2개, 6000/4000, 1~2구간 | 허용·배열 순서/배정 원금 유지 |
| 확정 뒤 변경, 세 번째 기업, 정원 마감 기업 | 기존 오류·무변경 |

수정/검증 후보: `Assets/Scripts/Rules/Market/{OrderValidator,MarketService,Settlement}.cs`, `Assets/Tests/Rules/Market/MarketServiceTests.cs`.

선택 취소 기본안은 **D의 로컬 후보 취소**다. B의 확정 원장을 지우거나 새로운 취소 API를 임의 추가하지 않는다. 후보 취소는 정원 변화 0, 최종 `SELECT_COMPANY` 성공만 정원 감소/차례 전진이다. 이미 확정한 선택을 취소해야 한다는 별도 요구가 확정되면 A와 차례 복원·마감·재전송·원장 계약을 먼저 정의한다.

BOT의 ‘최적’ 판단을 B가 대신해주지 않는다. `GetBundle`/정산 상세는 서버 전용으로 유지한다. A가 제시한 주문이 합법인지와 실제 손익만 검증한다. 기존 fixture의 P1=14280/P4=12750/P2=11080/P3=8900 회귀를 유지하고, 새로운 BOT 주문은 그 주문에 따른 별도 기대값을 계산한다.

통과 기준: **I02, I04~I05, S02~S04, B05~B07, R01~R02**. 인계: A/D에 합법·불법 주문 예제와 기존 오류 코드, C에 개인뷰에 실을 본인 주문 읽기 계약.

## NEXT-B02: 다음 단계의 정식 시장 생성기

차주10턴 진행의 선행 작업으로 착수한다. `DevFixtures.Synthetic`은 사인파 예제이므로 정식 난수 구현의 근거로 삼지 않는다. `MarketService(Func<int, MarketData>)`를 재사용하고02의 시장 규칙을 구현한다.

- 서버 한 곳에서 방별 seed와 턴별 결과를 생성/보관한다. 동일 방/턴의 재접속·구매·조회로 재추첨하지 않는다.
- 0일차0, 6기업×31값, 무료 서로 다른 2묶음을 전원 동일하게 제공한다.
- 기본 일일 증감 상한 bps: BANK80, FOOD120, AUTO350, AI/SPACE800, BIO1500. 정수 균등 추첨 값을 전날의 기준대비 값에 더한다.
- 기준대비 clamp bps: BANK600, FOOD800, AUTO2000, AI/SPACE5000, BIO8000. 턴별 일일 폭 배수는 `1+0.05*(turn-1)`로 10턴1.45배다. 정수 경계 반올림 방식은 테스트에 명시한다.
- seed 고정 재현성·기업별 상한·원본 복사·시장 턴 일치·과거 조회 유지와 일반 플레이 공급 경로를 검증한다. 기존 고정 시장은 별도 fixture 모드로 보존한다.

인계: A의 NEXT-A04가1~10턴을 실제 진행할 시장 공급 함수와 실행법. 3턴은 중간 검사이며10턴까지 시장/기록/이월을 확인한다. 임의의 수치 변경은02 및 기준 사례와 함께 검토한다. 통과 기준: **N01~N03**.

## NEXT-B03: 차주 비용·아이템/능력 효과·최종 집계

현재 `SettleTurn`은 비용0으로 계산하고 `IMarketService`에는 상점/입찰 비용 확정 메서드가 없다. B 소유 비용 원장·가용금 I·요청 키·실패 무변경 계약을 C/A와 먼저 정하고 차주 아이템/능력/입찰 전체에 연결한다. 비용 차감과 C의 지급·소모가 부분 적용되지 않게 검증/확정 경계를 정의한다.

02의 금융형4종, 고유능력5종의 배율·감산/보상·방어·기업 수익률 최저-100%·피해 상한·정수 반올림·효과 순서를 검증한다. 증폭기는 이익과 손실에 모두 적용하며1종 검증은 전체 완료가 아니다. 효과 없는 고정fixture의 기존 정산도 유지한다.

전광판에는 턴별/누적 성과·추이를 제공하고10턴 최종 승자는 자산→코인→최고 단일턴 수익률→시작 추첨순번 규칙을 적용한다. C 코인 조회와 A 추첨순번을 확정 시점의 스냅샷으로 받아 임의의 중복 잔액을 관리하지 않는다. 정산 상세의 타인 주문은 공개하지 않는다. 통과 기준: **N02~N06, N08~N11**.

```text
B 담당으로 NEXT-B01을 수행하라. 현재 실제 MarketService와 테스트를 재사용하라.

타인 주문이나 시장 원본을 UI/BOT 평가에 제공하지 마라.
기본 fixture 정산 회귀와 새 주문별 실제 결과를 구분해 보고하라.

```
