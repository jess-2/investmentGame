# A·B·C·D 통합과 턴 기록 보존

후속 TCP 게임 UI/BOT 대기실 연결은 [D 기록](../D/멀티플레이_UI_연결.md), 전체 현재 현황은 [04](../04_현재_구현_현황.md)를 따른다. 아래 `DevTabletBootstrap`의 메모리 전송 설명과70개 테스트 수는 B 통합 당시의 기록이다.

작성일: 2026-11-02. 기준: `prototype-v2` / `rules-v2`, Unity `6000.3.27f1`.
작업 브랜치: `feat/b-market-integration-history`.

## 현재 실행 경로

- `DevTabletBootstrap`: 실제 `MarketService` → `DevInformationService`의 실제 C 위임 → A `GameRoom` → D 컨트롤러·화면.
  상대 3명은 개발용 봇이며 통신은 기존 `LocalRoomHost`의 메모리 전송 + Unity JSON 복사다.
- `BlackWhale → A Multiplayer Lab`: 고정 시장 입력과 실제 B·C를 사용하는 TCP 호스트/클라이언트.
- `NetworkSession.Host`: 같은 방의 B 인스턴스를 C 어댑터에도 전달한다.
  B 인스턴스는 방마다 새로 만든다.

```csharp
var market = new BlackWhale.Rules.MarketService(marketData);
var information = new BlackWhale.Rules.Information.SharedInformationService(market);
await networkSession.Host(market, information, displayName, allowLan: true);
```

D 개발용 경로에서 `DevMarketService`와 고정 기대 전광판 반환을 제거했다.
`DevFixtures`는 시장 입력만 읽는다. fixture가 없을 때 쓰는 예제 시장에서도 B가 주문에 따라 정산한다.
기대 전광판은 테스트의 비교 대상으로만 사용한다.
A의 기존 격리 테스트에는 의도적으로 Mock을 남기고, 실제 B·C TCP 통합 검증을 별도로 실행한다.

## 해결한 문제

- 시장 원본 배열·무료 공개 위치와 규칙 입력을 복사하여 진행 중 변경되지 않게 했다.
- 공급자가 반환한 시장의 `turn`과 시작 요청의 턴이 다르면 상태 변경 전에 거절한다.
- B에서 참가자당 기업 선택을 2개로 제한한다. 세 번째는 공통 오류 `SELECTION_COMPLETE`이며 D 안내도 추가했다.
- 잘못된 턴/단계의 주문 전체 잠금을 거절하고, 과거 시장 전체 공개는 정산 완료한 턴에만 허용한다.
- D 화면·통합 테스트·A 진단 창의 어셈블리 참조와 서비스 생성을 실제 B에 맞췄다.

## 보존 범위와 수명

보존은 **해당 게임 세션의 서버 메모리**에 적용된다. 파일/DB 저장이나 호스트 종료 후 복원 기능은 추가하지 않았다.

- B: 턴별 전체 시장/무료 위치, 본인 선택 기업·확정 주문·자산, 공개 전광판·수익률 추이, 개인/기업별 정산 상세.
- C: 턴별 구매 원장·재전송 캐시·그 턴 마지막 코인 잔액. 이전 턴을 조회해도 현재 코인이 섞이지 않는다.
- 반환 배열·전광판·정산 상세는 복사본이다. 호출자가 수정해도 서버 기록은 유지된다.
- 이전 턴의 새 구매는 `STALE_TURN`, 이미 처리한 요청 재전송은 원응답이다. 늦게 온 이전 턴 코인 지급은 무변경이다.
- 과거 정보 조회에도 C의 본인 열람 필터를 적용한다. 서버의 전체 시장과 타인 주문은 공개 메시지에 추가하지 않는다.

서버에서 지난 턴 본인 화면을 조합할 때는 같은 턴의 B 상태를 C에 전달한다.

```csharp
var own = market.GetOwnInvestmentState(playerId, pastTurn);
var pastContext = new RequestContext(roomId, pastTurn, Protocol.Result, playerId);
var view = information.BuildPlayerView(pastContext, own);
var board = market.GetScoreboard(pastTurn);
```

전체 시장 조회 `GetBundle(turn, ...)`와 상세 `GetSettlementDetail(turn)`은 서버 전용이다.
과거 화면을 여는 새 UI나 네트워크 명령은 추가하지 않았다. 서버가 확인한 신원만 조회 문맥에 사용해야 한다.

## 검증

검증 명령:

```powershell
dotnet run --project Tests/AValidation/AValidation.csproj -- .
```

이 실행기는 기존 A 격리 검사와 실제 B·C TCP 접속·구매·재전송·재접속·1턴 전체 정산을 포함한다.
Unity EditMode에서는 B·C 보존/불변성/턴 검사와 실제 A+B+C+D 화면 상태 흐름도 함께 확인한다.
최종 실측 결과:

- .NET 10 실행기: **29개 통과**. 실제 B·C의 TCP 4소켓 구매·재전송·재접속·정산까지 포함한다.
  증거: `Logs/AValidation-results.json`.
- Unity `6000.3.27f1` EditMode: **70/70 통과, 실패·건너뜀 0**.
  원본 에디터를 유지하기 위해 임시 프로젝트 복사본에서 실행했다.
  증거: `Logs/BCIntegration-Unity-results.xml`, `Logs/BCIntegration-Unity.log`.
- 기본 fixture 최종 자산: P1 14,280 / P4 12,750 / P2 11,080 / P3 8,900 일치.
  D 통합 검사에서 P1의 AI 구간만 0→5일로 변경하면 P1 자산 9,480과 새 순위로 바뀌는 것도 확인했다.
- 회귀 사례: 시장·규칙 원본 변경 차단, 잘못된 시장 턴의 무변경 거절, 세 번째 기업 선택 거절,
  2턴 시작 후 1턴 시장·본인 주문·정산·코인·열람정보 보존, 반환 객체 변경 시 원본 보존,
  과거 턴 신규 구매 거절과 이전 처리 재전송·늦은 지급의 무변경 처리.

## 남은 범위

A 진행은 기본 1턴 후 종료를 유지한다. 난수 시장·10턴 진행·입찰·아이템·능력은 이번 범위에 넣지 않았다.
과거 조회/2턴 보존 검사는 서비스 계층에 직접 턴 시작을 주입하여 검증한다.
실제 4대 PC·플레이어 빌드·화면 렌더링 검증은 별도다.
