# 현재 구현 사항과 차주 구현 예정 사항

작성·갱신일: 2026-11-02. 현재 코드, 10주차 개선사항, 사용자가 추가한 차주 목표를 반영한 통합 요약이다. 차주 항목은 구현 목표이며 아직 완료된 기능이 아니다.

## 현재 구현 사항

현재는 **실제 TCP 멀티플레이로 1턴의 전체 게임 흐름**을 진행할 수 있다.

```text
방 생성/참가 → 4명 준비 → 정보 구매 → 기업 선택
→ 투자 비중·진입/청산 입력 → 시장 공개 → 정산·순위 → 종료
```

| 구분 | 구현된 내용 |
|---|---|
| A: 멀티플레이·진행 | TCP 방 생성/참가, 4인 정원, 준비/시작, 서버 단계·타이머, 시간 초과 자동 행동, 요청 재전송·중복 처리 방지, 개인/공개 정보 전송 분리, 토큰 재접속 |
| B: 시장·투자·정산 | 6개 기업의 원본 시세와 공개 정보, 기업당 정원 2명·플레이어당 기업 2개, 주문 검증·잠금, 실제 손익·자산·순위 계산, 턴별 시장·주문·정산 기록 보존 |
| C: 정보·코인 | 코인 지급·이월·차감, 정보 구매 기록, 공개 정보와 본인 구매 정보로 개인뷰 생성, 타인 정보 격리, 배열 복사를 통한 원본 보호 |
| D: 화면·입력 | 접속·대기실·정보 구매·기업 선택·투자 주문 화면, 꺾은선 그래프, 숫자로 진입/청산 입력, 타이머·오류 안내·전광판·수익률 추이 |
| BOT | 방장이 대기실에서 추가/제거 가능. 사람과 같은 명령 경로로 준비·기업 선택·주문·단계 완료 수행 |

현재 정보 단계는 **50초**다. BOT은 정보를 구매하지 않고 정해진 기업 선택 순서와 **60:40·10→15일/5→10일** 주문을 사용한다. 일반 플레이의 정식 난수 시장, 게임 흐름의 복수 턴·10턴, 입찰·상점·아이템·능력은 아직 구현되지 않았다. B/C 서비스의 과거 턴 보존과 실제 게임의 복수 턴 진행은 구분한다.

## 차주 구현 예정 사항

차주 목표는 **10턴 전체 게임과 3·6·9턴 입찰을 연결하고, 전광판·고유능력·아이템·UI를 구체화하며, 난이도에 따라 정보를 구매하고 투자하는 BOT을 구현하는 것**이다. 이전 문서에서 차주 이후로 분류했던 10턴·입찰·능력·아이템도 이번 차주 범위에 포함한다.

1. **10턴 구현:** 1~10턴 진행, 턴별 시장·선택·주문 초기화, 자산·코인·기록 이월, 10턴 최종 정산·승자 판정. **3·6·9턴 시작에 입찰 시스템**을 추가한다.
2. **전광판·고유능력·아이템 구현:** 기존 기본 전광판을 10턴의 성과·순위·이벤트와 연결하고, 능력 선택/발동과 아이템 구매·보관·사용·정산 효과를 구현한다.
3. **UI 구체화:** UI 레퍼런스를 바탕으로 정보 탐색·입찰·선택·시장 공개·결과에 긴장감과 속도감이 느껴지는 화면을 구성한다. 기존 막대·마우스 조작 개선도 유지한다.
4. **정보 기반 BOT과 난이도:** 난이도에 따라 스스로 정보를 구매하고, 본인이 열람한 정보를 평가해 기업·진입/청산·비중을 결정한다.

| 구현 항목 | 현재 상태 | 차주 목표 | 담당 |
|---|---|---|---|
| 10턴 진행 | 1턴 정산 후 종료 | 1~10턴 연속 진행, 턴별 초기화/이월, 자리 순환, 최종 승자 판정 | A 진행, B/C 상태, D 표시 |
| 3·6·9턴 입찰 | 미구현 | 3턴 블랙박스 분석권, 6턴 프리패스, 9턴은 9·10턴 선택 우선순위 입찰 | A 단계, C 입찰, B 비용, D 화면 |
| 전광판 | 기본 자산·순위·수익률 표시 | 턴별/누적 성과·추이·순위 갱신, 입찰/능력/아이템 공개 이벤트, 최종 결과 | B 집계, A 전송, D 화면 |
| 고유능력 | 미구현 | 정치인·작전 세력·정보상·기업사냥꾼·도박사의 선택·발동·제한·효과 연결 | C 원장, B 효과, A 진행, D 화면 |
| 아이템 | 미구현 | 상점·인벤토리·구매/사용 제한, 금융/정보/공격 아이템과 프리패스 효과 | C 원장, B 비용/정산, A 검증, D 화면 |
| UI 구체화 | 기능 확인 중심 개발 화면 | 레퍼런스의 화면 구성·정보 위계·색·모션을 반영하고 입찰/공개/결과 연출 강화 | D 주담당 |
| 일별 시세 그래프 | 꺾은선이라 기준일 대비 증감 파악이 어려움 | 0일차 대비 양/음 막대와 날짜·% 표시, 미열람과 0% 구분 | D |
| 진입·청산 선택 | 날짜를 숫자로 입력 | 마우스로 진입일·청산일 지정, 후보 취소·완성 구간 삭제/재선택 | D, B 검증 |
| 기업 표시 | 기업 ID·텍스트 중심 | 기업 이름과 이미지 표시, 이미지가 없어도 대체 표시 | D |
| 투자 자리 선택·취소 | 클릭 즉시 서버 확정 | 후보 선택→취소/교체→명시적 확정 방식 도입을 권장 | D, A/B 연결 |
| 타인 선점 표시 | 잔석 숫자와 점 표시 | 정원 2칸의 빈자리·내 확정·익명 선점을 명확히 구분 | D |
| 정보 기반 BOT | 정보 구매 없이 고정 선택·주문 | 자기 정보 구매→개인뷰 재평가→기업·합법 구간 선택 | A, C/B 지원 |
| BOT 난이도 | 하나의 고정 전략 | 쉬움/보통/어려움 정책과 대기실 설정 | A 정책, D 화면 |
| 정보 시간 | INFO 50초 | **1분 30초(90초)**와 서버 마감 기준 표시 | A, D 표시 |

자리 취소의 **권장 범위는 서버 확정 전 로컬 후보 취소**다. 서버 확정 후 차례를 되돌리는 취소는 별도 규칙·계약이 필요하다. 기업별 선점 상태는 강조하되 타인의 투자 명단·주문은 공개하지 않는다.

INFO를 90초로 늘리고 다른 단계 시간을 유지하면 일반 턴 최대 시간은 **120초→160초**가 된다. 전원 완료 조기 진행은 유지하는 안이다. 기존 고정 데이터 검사는 50초 설정으로 보존하고, 새 플레이에 90초 설정을 적용한다.

입찰턴은 **입찰15초+INFO90초+선택32초+주문23초+공개10초+결과5초=최대175초**를 계획 기본안으로 둔다. 능력 선택은 1턴 시작 전 준비 흐름에 연결하며 세부 선택 시간은 구현 계약에서 정한다. UI 연출 때문에 서버 마감을 추가로 늘리지는 않는다.

능력·아이템의 종류/가격/효과/상한과 입찰 세부 규칙은 [02 확정 규칙](./02_결정_사항.md)을 재사용한다. UI 레퍼런스의 구체 파일/URL은 아직 본 가이드에서 특정하지 않았으므로 구현 시작 시 사용할 자료와 적용 요소를 기록한다. 정식 레퍼런스가 지정된 것처럼 임의 출처를 만들지 않는다.

## 담당별 차주 작업과 진행 순서

| 담당 | 우선 작업 | 완료 확인 |
|---|---|---|
| A | 10턴/INFO90초/입찰 단계·능력 선택 흐름, 명령/이벤트 계약, 정보 기반 BOT·난이도 | 1~10턴 단절 없이 진행, 3·6·9턴만 입찰, 중복 진행·정산 방지 |
| B | 턴별 시장 공급, 비용·아이템/능력 효과·최종 승자 집계, 주문 회귀 | 비용/효과 순서·상한·반올림·자산 이월·기본 손익 회귀 유지 |
| C | 정보 격리, 입찰/보상, 상점/인벤토리·능력 선택/상태·사용 원장 | 실패 무변경, 비용과 지급/소모 일관성, 턴 제한·쿨다운·중복 방지 |
| D | 레퍼런스 기반 UI, 10턴 전광판·입찰·능력/아이템 화면, 막대/마우스 입력과 BOT 설정 | 실제 조작·서버 이벤트 연출·개인/공개 정보 구분·최종 결과 확인 |

A/B/C가 턴·입찰·비용·효과·능력 선택의 Shared 계약을 먼저 맞춘다. 3턴 중간 검증은 **10턴 구현을 위한 체크포인트**로 사용하고 완료 목표를 대체하지 않는다. 이후 6·9턴 입찰과 효과를 연결하여 10턴까지 확인한다. D는 계약에 맞춰 레퍼런스 기반 화면을 구성하고, BOT을 연결해 **사람1+BOT3 / 사람2+BOT2 / 사람4**의 TCP 10턴 전체 흐름을 검증한다. BOT의 입찰/능력/아이템 단계에는 합법 입력 또는 서버 기본값을 적용해 진행이 멈추지 않게 한다.

## 검증 기준과 차주 완료 조건

차주 완료는 **10턴 최종 종료, 3·6·9턴 입찰, 고유능력5종과 아이템 효과, 10턴 전광판, 레퍼런스 기반 UI, 난이도별 정보 구매·투자 BOT**을 실제 게임 흐름에 연결한 상태를 뜻한다. 증폭기1종이나 3턴만 검증한 상태는 중간 성과로 기록한다. 미구현/미검증 항목은 별도로 남기며 구현된 것으로 표시하지 않는다.

상세 근거는 [04 현재 현황](./04_현재_구현_현황.md), 실행 명세는 [05 다음 계획](./05_다음_구현_계획.md), 검사 방법은 [06 검증](./06_다음_구현_검증.md)에 있다. 담당별 구체적인 작업은 [A](./A/다음_구현_작업지침.md), [B](./B/다음_구현_작업지침.md), [C](./C/다음_구현_작업지침.md), [D](./D/다음_구현_작업지침.md)를 따른다.
