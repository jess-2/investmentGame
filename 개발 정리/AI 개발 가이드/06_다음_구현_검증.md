# 다음 구현 검증과 완료 기준

새 기준의 정식 목록은 [다음_구현_통과기준.json](./다음_구현_통과기준.json)에 있다. 상태는 전부 `NOT_RUN`에서 시작한다. 이 목록은 검증 명세이며 자동으로 Unity 테스트를 실행하는 파일이 아니다. 기존 `A~D/통과기준.json`은 `basic-turn-v2` 회귀 기대값으로 유지한다.

사용자 추가 차주 범위를 반영해 **기존27개+확장12개=39개** 명세로 갱신했다. 기존 R03의1턴 실행은 회귀로 유지하고 아래 N01~N12에서10턴·입찰·능력·아이템·전광판·레퍼런스 UI의 완료를 확인한다.

## 실행 순서

작업 디렉터리는 **Unity 프로젝트 루트 `BlackWhale/`**다.

```powershell
python "개발 정리/임시 데이터 및 검증용/validate_fixtures.py"
python "개발 정리/AI 개발 가이드/build_packages.py" --check
python "개발 정리/AI 개발 가이드/validate_next_guide.py"
dotnet run --project Tests/AValidation/AValidation.csproj -- .
```

위 Python 검사는 데이터·문서·명세의 일관성만 확인한다. `.NET`의 29개 기준은 현재 코드에서 실행한 회귀 기준이며 새 UI·난이도 검사를 포함하지 않는다. 새 기능을 구현할 때 해당 Case ID를 C#/Unity 테스트에 매핑하고 실행 결과를 별도 기록한다.

Unity에서는 Test Runner로 기존 EditMode 전체와 신규 순수 정책/초안 검사를 실행한다. 실제 마우스 hit test, Canvas 크기 변환, 툴팁, 버튼 1회 클릭, pending 중 입력 차단은 PlayMode 또는 실제 화면에서 확인한다. 기존 73개 테스트의 통과 기록을 새 기능 테스트 결과로 재사용하지 않는다. 열려 있는 사용자의 Unity 작업을 중단하거나 씬을 덮어쓰지 않는다.

N08은 능력5종 각각, N10은 아이템9종 각각의 성공/실패·경계·복합 사례로 세분화한다. 상위 Case가 하나라고 단일 효과 검사만 실행하지 않는다. 기본1턴 회귀 통과와10턴/전체효과 구현 완료는 별도 보고한다.

BOT 정보 격리 검사는 **허용된 개인뷰와 seed를 동일하게 고정하고 서버의 미열람 시세만 바꿔도 행동이 같은지** 확인한다. 반대로 같은 후보의 알려진 끝점 값을 바꾸는 설계 사례에서는 보통/어려움의 평가/선택이 바뀌는지 확인한다. 전자는 숨은 정답 접근 방지, 후자는 정보 이용의 증거다. 테스트 fixture를 봇의 프로덕션 전략에 주입하지 않는다.

막대의 일별 값과 구간 수익을 혼동하지 않는다. 10일 -40%, 15일 +30% 막대는 각각 그 높이로 표시하고, 선택한 10→15일 구간의 수익률은 **+70%p(7000bps)**다. 이것이 포트폴리오 전체 +70%라는 뜻도 아니다.

## 제출 형식

각 작업은 변경 파일, NEXT 작업 ID와 Case ID, 입력→실제→기대 비교, 실행 명령/환경, 로그 경로, 미실행 항목, 다른 담당에게 넘길 계약을 보고한다. 결과는 `Logs/Next-<작업ID>-results.*` 등 별도 파일로 남기고 기대 JSON의 `NOT_RUN`을 임의로 PASS로 덮어쓰지 않는다.

완료 조건은 ① 개선사항의 실제 동작, ② 담당 Case 통과, ③ 기존 회귀 통과, ④ 실제 UI/TCP 연결, ⑤ 확인하지 못한 환경 명시다. 문서/정답 JSON만 추가했거나 BOT의 잔액만 바뀌었다면 기능 완료가 아니다.
