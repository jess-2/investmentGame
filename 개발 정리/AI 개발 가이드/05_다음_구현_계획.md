## 먼저 적용할 규칙과 제안의 구분

**사용자 요구로 반영할 사항:** 10턴·3/6/9턴 입찰·전광판·고유능력·아이템·레퍼런스 기반 UI와 기존 일별 막대, 마우스 진입/청산·취소, 기업 이미지, 자리 상태 강조, 정보 기반 BOT·난이도, INFO90초.

**구체적인 구현을 위한 권장안:** 후보 확정 전 취소 범위, 클릭 방식, 난이도별 예산/탐색 규칙은 아래 기본안으로 작업을 시작한다. 원문에서 세부 동작까지 확정한 것으로 기록하지 않는다. 특히 서버 확정 후 선택 취소는 현 차례를 이미 전진시켰으므로 별도 규칙 결정과 A/B 계약 변경이 필요하며, 후보 취소 구현만으로 그 기능까지 완료했다고 보고하지 않는다.

### 시간 변경과 기존 fixture

| 구분 | INFO | 선택 | 주문 | 공개 | 결과 | 최대 합계 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 `basic-turn-v2` 회귀 | 50초 | 32초 | 23초 | 10초 | 5초 | 120초 |
| 다음 플레이 기본값 | **90초** | 32초 | 23초 | 10초 | 5초 | **160초** |
| 다음 입찰턴 기본안 | **90초** | 32초 | 23초 | 10초 | 5초 | **175초(입찰15초 포함)** |

90초는 INFO의 **최대 대기 시간**이다. 기존 전원 완료 조기 진행은 유지하는 안이다. 현재4초 선택·23초 주문을 줄여120초를 맞추지 않는다. 차주3·6·9턴은 입찰15초를 INFO 앞에 추가하는 **최대175초**를 계획 기본안으로 쓴다. 입찰턴 INFO를 이전35초로 줄이는 규칙은 기존 회귀 자료에만 남긴다. 최종 시간 설정은 A가 하나의 서버 설정으로 정의하고 관련 테스트를 맞춘다.

`GameRoom`에 서버용 진행 시간 설정을 주입하는 방식으로 50초와 90초를 분리한다. 이름은 제안이며 실제 클래스는 구현 시 정한다. 기존 fixture/재생 검사는 명시적으로 50초 설정, 실제 호스트 기본값은 90초 설정을 사용한다. 현재 `Protocol.RulesVersion`은 `rules-v2`이고 별도 협상도 없으므로 문서만으로 새 통신 버전이 생겼다고 가정하지 않는다. 설정을 전송해야 할 경우 A가 Shared 선언·복사·코덱·예시를 함께 갱신한다. 시간 표시 자체는 기존 서버 마감 DTO로 가능하다.

기존 16개 fixture와 역할 JSON의 50초·74초 선택 완료·97초 주문 마감을 전역 치환하지 않는다. 새 90초 검사를 별도로 추가한다. 모두 3초씩 선택하는 새 시나리오는 90→114초 투자 시작→137초 주문 마감이고, 전혀 입력하지 않으면 90→122→145→155→160초다.

### 그래프와 날짜 클릭

- 막대 하나는 **해당 날짜의 0일차 대비 변화율**이다. 전일 대비 증감, 5일 평균, 캔들 시세로 바꾸지 않는다. `-4000bps`는 `-40%`, `3000bps`는 `+30%`다.
- 0% 선 위/아래로 양/음 막대를 그린다. 알려진 0%는 0% 표식과 툴팁을 주고, 미열람 날짜는 공백/잠금으로 구분한다. 축과 툴팁도 `PlayerView`와 공개 설정만 읽는다.
- 정보 구매창과 투자 주문창을 먼저 교체한다. 시장 공개 후 기업 시세도 같은 막대로 표시하되 전광판의 **플레이어 누적 수익률 추이**는 별도 의미이므로 꺾은선을 유지할 수 있다.
- 날짜 클릭 기본안: 1회 클릭=진입일 후보, 다음 클릭=청산일 후보. 0~30 정수일로 스냅하고 선택한 날짜/보유일수를 표시한다. 진입일 앞/동일 청산, 4일/11일 보유, 겹침, 3개째 구간은 초안에 반영하지 않고 이유를 표시한다.
- 우클릭 또는 ‘선택 취소’로 진행 중 후보를 지운다. 완성한 구간은 기존 `RemoveInterval`로 삭제/다시 선택한다. 빈 초안도 허용하되 주문 확정은 기업당 1~2개 합법 구간이 있을 때만 가능하다.
- 미열람 날짜에도 거래를 예약할 수 있다. **막대가 아닌 날짜 영역 전체**에 클릭 판정을 두고, 숨겨진 값의 높이를 클릭 계산에 쓰지 않는다. 선택 음영·마커는 값이 없어도 날짜로 그린다.
- 초안 조작 중에는 서버에 주문을 보내지 않는다. ‘주문 확정’ 한 번만 기존 `SUBMIT_INVESTMENT`를 사용한다. 응답 대기/잠금/단계 종료 후에는 추가 클릭과 취소를 막는다. 기존 숫자 입력은 보조 수단으로 유지할 수 있다.

### 기업 카드와 자리 선택 취소 기본안

기업 ID `AI/SPACE/FOOD/BANK/BIO/AUTO`는 통신·규칙에서 유지한다. D의 표시용 카탈로그에 표시명과 Sprite를 매핑한다. 원문에 정식 회사명/이미지가 없으므로 AI·우주·식품·은행·바이오·자동차 계열의 임시 표시임을 개발 자료에 적고, 이미지가 없어도 텍스트 카드로 동작하게 한다. 표시용 에셋에 시장 원본을 넣지 않는다.

후보 선택은 클라이언트 임시 상태이며 정원을 예약하지 않는다. 같은 후보 재클릭/취소 버튼으로 해제, 다른 기업 클릭으로 교체, ‘선택 확정’에서 기존 `SELECT_COMPANY`를 1회 전송한다. 서버 성공 뒤에는 ‘내 확정’으로 표시하고 다음 차례를 따른다. 4초가 지나면 후보는 폐기하고 기존 서버 자동 선택을 따른다. 시간이 짧으므로 후보/확정 버튼과 남은 초를 한 화면에 놓고 실제 사용성을 확인한다.

2칸 표시는 공개 `remainingSeats`와 본인 `selectedCompanies`만으로 만든다. 예를 들어 잔석 1/본인 미선택이면 ‘선점됨 1 + 빈자리 1’, 잔석 0/본인 선택이면 ‘내 확정 1 + 선점됨 1’이다. 타인의 이름·정확한 투자 명단·주문을 공개 DTO에 추가하지 않는다. 로컬 후보가 있어도 새 공개 상태가 정원 마감을 알리면 확정을 막고 안내한다. 최종 경합 검증은 B가 한다.

### BOT 정보 이용과 난이도 기본안

`DevBot`의 fixture 재생은 회귀용으로 남기고, 일반 플레이 전략을 별도로 주입한다. BOT은 자기 `PlayerView`·공개 상태만 입력받으며 `MarketService`, `GetBundle`, 정답 JSON 또는 `DevFixtures.ReplayPicks`를 전략에서 읽지 않는다. 주문 공개 전에는 전체 시세를 쓸 수 없다.

| 난이도 | 구매 정책 기본안 | 평가/주문 정책 기본안 |
|---|---|---|
| 쉬움 | 턴당 최대 1묶음, 잔액 이내 | 알려진 양 끝점의 합법 1구간 중 양의 구간을 우선, 후보 중 seeded 무작위 선택. 근거 없으면 합법 기본 주문 |
| 보통 | 턴당 최대 2묶음, 잔액 이내 | 알려진 양 끝점으로 모든 합법 1구간 평가, 수익 차이 상위 기업/구간 선택 |
| 어려움 | 턴당 최대 3묶음, 잔액 이내 | 합법 1~2개 비중복 구간의 합을 비교하고 5:5/6:4/7:3 중 평가값이 좋은 배분 선택 |

구매 대상은 아직 미열람인 묶음 중 ‘알려진 날짜와 합법 구간의 끝점을 만들 수 있는 묶음’을 우선하고 동점은 전략용 seed로 고른다. 구매 뒤 새 개인뷰/결과를 반영하여 다시 평가한다. 0일차는 알려진 0이며 미열람 날짜는 0으로 간주하지 않는다. 같은 정보로 수익을 보장하지 않으며 어려움에 추가 자산/코인·숨은 정답 접근을 주지 않는다.

INFO 상태는 평가→구매 요청→응답 대기→재평가→예산/후보 소진→완료로 나눈다. 실패·재전송·기한 임박에도 중복 구매/무한 반복 없이 완료해야 한다. 자기 차례에는 정원·본인 중복을 제외하고 평가 상위 기업을 고르며, 불가능하면 공개 상태만으로 합법 대체 선택을 한다. 투자도 기존 B 검증을 통과하는 주문만 전송한다. 난이도는 최초 방 전체 설정을 기본안으로 하고, 대기실에서만 변경한다. BOT별 설정은 후속 확장이다.

## 차주 확장 기능의 구현 순서

다음 작업은 모두 차주 목표에 포함한다. 3턴과 증폭기1종을 먼저 확인하는 것은 중간 검증 순서이며 최종 범위를 줄이는 의미가 아니다.

1. **NEXT-B02 정식 시장 공급자:** 02의 서버 난수/고정 seed, 31일·공개 2묶음·기업별 일일/누적 상한·턴별 변동폭을 적용한다. 같은 방/턴은 재생성하지 않는다. 공개 2묶음은 중복 없이 서버 1회 선택한다.
2. **NEXT-A04 10턴 진행:** B 공급자를 `Func<int, MarketData>`에 연결하고 turn 증가, 8회 선택/잠금/완료 집합 초기화, 시작 추첨순서 보관과 자리 순환, 자산/코인/인벤토리/능력 상태 이월을 연결한다. 3턴으로 중간 검증한 뒤1~10턴을 진행하고10턴 최종 승자 판정 후 종료한다.
3. **NEXT-C02 + NEXT-B03 증폭기부터:** 기존 확정 규칙에 맞춰 상점 비용·인벤토리·턴당 구매/사용 제한을 정의하고, B의 자산 원장과 C의 효과 원장을 멱등 연결한다. 현재 `IMarketService`에 비용 확정 API가 없으므로 Shared 계약을 먼저 작성한다. 증폭기는 기업 수익률×2이고 손실에도 적용한다.
4. **NEXT-A05/C03 3·6·9턴 입찰:** AUCTION 단계·비밀 금액·확정·마감/미제출·낙찰·비용·보상·9/10턴 자리 배정을02대로 연결한다. 3턴은 블랙박스 분석권, 6턴은 프리패스, 9턴은 자리 우선순위이며10턴에는 재입찰하지 않는다.
5. **NEXT-A06/C04 고유능력:** 게임 시작 전 무작위3개 후보 중1개 선택/기본 선택을 연결하고 정치인·작전 세력·정보상·기업사냥꾼·도박사5종을 구현한다. 개인 능력 상태·쿨다운·무료권·방어·정산 효과와 재접속 복원을 검증한다.
6. **NEXT-D05 전광판:** 턴별/누적 성과·순위·추이·공개 효과/입찰 결과·10턴 최종 승자 화면을 구현한다. 본인 과거 조회는 권한을 확인한 A 경로로 연결하고 타인 주문/구매정보는 공개하지 않는다.
7. **NEXT-D06 아이템/능력/입찰 화면 + NEXT-D07 UI 구체화:** 실제 계약을 사용해 구매·사용·선택·확정/대기/오류 상태를 연결한다. UI 레퍼런스의 구성·색·글꼴·정보 위계·전환/강조 연출을 화면에 적용한다.

아이템 범위는 증폭기·하락 파쇄기·방패·대폭발 탐지기·블랙박스 분석권·정보 왜곡·정보 훔치기·수익률 감소·블랙웨일 프리패스다. 상점/보유/분류별 사용 제한, 유효 사용 소모, 정산 순서/상한, 효과 출처는02를 따른다. 증폭기1종만으로 전체 아이템 구현 완료를 표시하지 않는다.

레퍼런스의 구체 파일/URL은 아직 가이드에 특정되어 있지 않다. D는 구현 시작 시 실제 사용할 자료와 화면별 적용 요소를 기록하고, 정보 탐색·입찰 마감·기업 선택·시장 공개·순위 변화/최종 결과의 긴장감과 속도감을 설계한다. 연출 중에도 마감/조작 상태·숫자·미열람 정보가 명확해야 하며 서버 단계를 임의로 지연하지 않는다.

전체 통합은 사람1+BOT3/사람2+BOT2/사람4 구성으로10턴 종료까지 확인한다. 기존 R03의1턴 검사는 회귀로 유지하고 N01~N12에서 확장 범위를 검사한다. BOT의 입찰·능력 선택은 합법 입력/서버 기본값을 제공해 정보 구매 전략과 별개로10턴 진행이 막히지 않게 한다.

세부 기획이 없는 이미지의 정식 이름/에셋, 후보 취소를 넘어선 서버 확정 취소, 난이도별 수치 조정은 구현 보고에서 제안/채택 여부를 남긴다. 이 문서에 적힌 새로운 클래스명과 정책 기본안은 현재 API가 아니다.
