## 공통 계약 제안과 연결 지점

기존 Shared가 없어 A가 제안한 첫 구현이다. **B/C/D의 사용 측 리뷰·공통 PR 병합은 아직 수행하지 않았다.**

- B: `IMarketService`를 구현한다. 선택 원장·정원·주문·자산·시장·손익 계산의 소유자는 B다.
- C: `IInformationService`를 구현한다. `GrantTurnCoins`는 방/턴 키로 멱등이어야 하며, 구매는 차감·원장 갱신을 원자적으로 적용한다.
- B→C: C는 서버 전용 `IMarketDataSource.GetBundle`로 B의 같은 시장에서 정보를 읽는다. 무료 위치를 다시 추첨하지 않는다. 검증용 C Mock도 이 인터페이스로 연결했다.
- A: `RequestContext`를 접속 연결에서 생성한다. 클라이언트 본문에 참가자 ID나 수신시각을 추가해도 신원/마감 판정에 사용하지 않는다.
- D: `IGameClient.MessageReceived` 또는 `NetworkSession.MessageReceived`를 구독한다. 개인뷰는 본인 연결로만 수신한다.
- 정산·시장 공개 시점: 미제출 주문 자동 확정 → `LockAllOrders` → 공개 그래프 → 공개 시간 종료 → `SettleTurn` → 전광판.

기존 `type/requestId/turn/payload`, bps와 정수 날짜, `recipientPlayerId/assets/coins/ownInvestments/companies` 형식을 유지했다.
개인뷰에는 `phase`와 **본인의** `selectedCompanies`를 추가했다. 후자는 주문 제출 전 재접속 시 선택 기업을 복원하는 데 사용한다.
`OwnInvestmentState.SelectedCompanies`도 B가 읽기 전용으로 제공한다.

선택 결과는 `SELECT_COMPANY_RESULT` envelope의 `payload.companyId`로 전달한다.
`ServerMessage.type`은 `WELCOME`, `PUBLIC_STATE`, `COMMAND_RESULT`, `PLAYER_VIEW`, `MARKET_REVEAL`, `SCOREBOARD`, `JOIN_REJECTED`, `ROOM_ENDED`, `DISCONNECTED`다.
`WELCOME`의 개인 재접속 토큰은 공개 roster에 포함하지 않는다. 접속 시 네트워크 버전 협상은 추가하지 않았다.

추가 A 명령은 `SET_READY`, `START_GAME`, `COMPLETE_PHASE`, `GET_PLAYER_VIEW`다.
`COMPLETE_PHASE`는 INFO/공개/결과에서 참가자별 완료를 모으며, 전원 완료 시 조기 진행한다.
투자 단계는 B가 4명 주문을 모두 잠그면 조기 진행한다. 수동 단계 제어 메서드는 네트워크로 노출하지 않는다.

추가 오류는 `ErrorCodes.cs`에 정의했다. 예: `INVALID_REQUEST`, `NOT_CONNECTED`, `ROOM_FULL`, `NOT_ALL_READY`, `HOST_ONLY`, `DEADLINE_EXCEEDED`, `INVALID_RECONNECT_TOKEN`.
기존 규약의 `REQUEST_ID_CONFLICT`, `RATE_LIMITED`도 구현했다. 호스트 종료/정상 종료의 이유는 `HOST_DISCONNECTED`/`GAME_COMPLETE`다.

## 진행·시간·재전송

- 일반턴: INFO 50초 → 선택 최대 32초(성공/자동 선택마다 최대 4초) → 투자 23초 → 공개 10초 → 결과 5초.
- 조기 진행하면 다음 단계 마감을 실제 전환시각부터 새로 계산한다. fixture의 마지막 선택 74초 → 투자 마감 97초를 재현한다.
- 실시간 모드는 단조 시계를 사용한다. 큰 시각 점프도 각 예정 마감 순서대로 자동 행동을 수행한다.
- 수동 모드는 자동 진행만 멈춘다. 명시적 단계 전환·요청 검증·마감 검사는 유지한다.
- 서버 수신 큐에 받아들인 시각을 A로 전달한다. 메인 스레드 처리가 늦어져도 마감 전 수신 요청은 인정한다.
- 새 요청은 마감 이상이면 거절한다. 이미 처리한 요청의 재전송은 시각·단계·요청 수 제한 검사 전에 캐시로 응답한다.
- 캐시 범위는 방 인스턴스/참가자/턴/requestId다. 본문 지문이 다르면 충돌, 같으면 복사된 원응답이다. 방 종료까지 유지한다.
- 참가자당 현재 서버 턴의 새 요청을 256개로 제한한다. 호스트도 다른 참가자와 동일한 TCP 클라이언트를 사용한다.
- 연결 끊긴 일반 참가자는 30초 미만에 개인 토큰으로 복귀할 수 있다. 시계는 계속 진행하고 슬롯·자동 행동을 유지한다.

## 직접 확인하는 방법

Unity 메뉴 `BlackWhale → A Multiplayer Lab`을 연다. 테스트 assembly가 컴파일된 Editor에서 제공된다.

1. `Host (fixture mocks)`로 로컬 호스트와 P1 클라이언트를 만든다. 기본 포트는 7777이다.
2. `Join / add local client`를 세 번 눌러 P2~P4 패널을 만든다. 패널마다 별도 TCP 연결이다.
3. 네 패널의 `Ready`를 누르고 P1의 `Start`를 누른다.
4. P1에서 `Buy AI bundle 1`을 눌러 P1에만 열람/코인 변화가 생기는지 확인한다.
5. 각 패널에서 정보 완료·차례별 기업 선택·주문 제출을 실행한다. 서버 시계를 사용하면 시간 초과 기본 행동도 확인할 수 있다.
6. 끝나면 `Close connections`를 누른다.

다른 PC에서는 호스트 주소/포트를 입력해 Join한다. 이 창의 호스트는 테스트용 Mock을 사용한다.
실제 B/C 연결은 별도 GameObject의 `NetworkSession.Host(actualMarket, actualInformation, name, port, allowLan: true)`로 한다.
다른 플레이어는 `NetworkSession.Connect(hostAddress, name, port)`를 호출한다. 2026-11-02부터 `DevTabletUI` 씬의 접속 화면에서 이 경로를 사용하며, 방장의 BOT 관리도 연결했다. [사용 절차](../D/멀티플레이_UI_연결.md)를 참고한다.
