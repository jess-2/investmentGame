## NEXT-A02: 개인 정보로 투자하는 BOT

현재 `UI/Dev/DevBot.cs`는 `ReplayPicks`와 고정 주문을 사용한다. 회귀용 재생 전략과 일반 플레이 전략을 분리한다. 전략은 가능하면 Unity 시간/렌더에 의존하지 않는 C#으로 두고, 호스트가 수명·클라이언트·업데이트를 관리한다. 새 `Bots` 어셈블리를 쓰려면 참조/`.meta`를 함께 추가하되 이름은 구현 시 정한다.

- 전략 입력: 본인 `PlayerView`, 공개 `PublicState`, seeded 난수, 난이도 설정. 시장 서비스·B/C 내부 객체는 생성자에 넘기지 않는다.
- C 제공 예제를 이용해 INFO에서 미열람 묶음만 `BuyInformation`으로 구매한다. 구매 pending이면 새 구매/완료를 보내지 않고 결과/갱신 후 재평가한다. 재시도 상한·기한 임박 fallback을 둔다.
- 알려진 0일차와 묶음 `startDay`를 날짜 배열로 펼친다. 합법 구간 끝점이 모두 알려졌을 때 `exitBps-entryBps`로 평가한다. 모르는 값을 0으로 채우거나 서버에서 보충하지 않는다.
- 기업 선택은 매 차례 공개 잔석·자기 선택을 다시 검사한다. 고정 기업/순서를 쓰지 않고 평가 상위 후보를 고른다. 구간 1~2개·비중 합10000·중복 기업 금지 등 기존 B 규칙을 통과하는 주문을 만든다.
- 응답 대기/거절/마감/자동 주문과 경합해도 중복 주문을 보내거나 영구 정지하지 않는다. 전략 결과가 없으면 공개 정보만 사용하는 합법 기본 주문으로 끝낸다.
- 봇도 사람과 같은 `GameClientController`와 TCP로 명령을 보낸다. fixture 재생은 테스트에서만 명시적으로 선택한다.

통과 기준: **B01~B03, B05~B07, R02~R03**. 인계: C에 실제 구매 로그/격리 검사, B에 생성 주문과 검증 결과.

## NEXT-A03: 난이도 설정 연결

쉬움/보통/어려움은 [정책 기본안](../05_다음_구현_계획.md)을 사용하고 예산·구간 탐색·동점 선택을 설정으로 분리한다. ‘어려움은 항상 이김’은 완료 기준이 아니다. 동일 입력+seed의 재현성과 다른 판단 범위를 검사한다.

현재 방장 프로세스만 BOT을 생성하므로 첫 구현은 방 전체 대기실 설정을 주입하는 방식으로 가능하다. D에 설정 변경 진입점을 제공하고 기존 BOT에도 적용할지 재생성할지 명시한다. 기본안은 대기실의 기존/신규 BOT 모두 같은 설정을 사용하고 게임 시작 후 고정이다. 다른 참가자에게 표시해야 한다면 Shared 공개 필드·복사·codec을 한 변경으로 다룬다. 기존에 `botDifficulty` 필드가 있다고 가정하지 않는다.

수정 충돌 주의: `DevTabletBootstrap`, `LobbyActions`, 난이도 버튼을 A/D가 동시에 수정하지 않도록 A가 생성/설정 API, D가 버튼 연결을 맡는다. 통과 기준: **B04, R03**.

## NEXT-A04~06: 차주10턴·입찰·능력 선택 진행

이 작업도 차주 목표다. NEXT-A04는 현재 `BeginTurn`의 turn=1뿐 아니라 `selectionIndex`, `ordersLocked`, 완료/차례 상태, 시작 추첨순서와 매 턴 시간 기준을 정리한다. RESULT 뒤 다음 턴을 시작하고10턴 결과/최종 승자 판정 후 종료한다. B의 턴별 시장 공급자와 C의 자산 외 상태 이월을 연결한다. 3턴 실행은 중간 체크포인트이며10턴 완료를 대체하지 않는다.

NEXT-A05는3·6·9턴 시작에만 AUCTION을 진입시키고 입찰 검증·확정·마감·미제출·낙찰·비용/보상 처리를 C/B와 연결한다. 9턴 결과로9·10턴 자리를 배정하고10턴 재입찰은 하지 않는다. 계획 시간은 입찰15초+INFO90초로 입찰턴 최대175초다. 입찰 금액은 개인 응답/서버 내부에 두고 공개 이벤트는 허용된 결과만 전달한다.

NEXT-A06은 게임 시작 전 능력3후보/1선택과 미선택 기본값을 C에 연결한다. 능력 선택 단계/명령/마감의 정확한 계약은 Shared에 먼저 정의하고 초기 지급·인벤토리·쿨다운 복원과 상태 일관성을 확인한다. 능력 선택 시간은 아직 별도 확정하지 않았으므로 기존 턴 마감에 임의로 끼워 넣지 않는다.

아이템/능력/입찰 요청도 신원·단계·턴·수신시각·요청 키 검사를 동일하게 적용한다. 전광판 이벤트·새 DTO의 깊은 복사·정수 검증·재접속 상태를 함께 갱신한다. BOT은 능력/입찰 입력 또는 합법 기본값을 사용해10턴 흐름이 막히지 않게 한다. 통과 기준: **N01~N08, N10~N11**, 비용/효과는 B/C와 공동 검증한다.
