# D 다음 구현: 막대·마우스 날짜·기업 이미지·자리 취소

[현재 현황](../04_현재_구현_현황.md), [다음 계획](../05_다음_구현_계획.md), [검증](../06_다음_구현_검증.md), 공통 00~03과 실제 UI 코드를 먼저 읽는다. `DevTabletUI`는 현재 TCP로 동작한다. 테스트 대역으로 게임 경로를 되돌리지 않는다.

## NEXT-D01: 일별 막대 그래프

현재 `InfoPurchasePage.CompanyCard.DrawChart`와 `InvestmentPage.DrawOrderChart`는 `LineChartGraphic`을 사용한다. 두 화면에서 같은 막대/날짜 좌표 규칙을 쓰도록 공통 Graphic/표현 모델을 구성한다. 새 `BarChartGraphic` 이름은 제안이다. 기존 `LineChartGraphic`은 전광판 추이에서 계속 사용할 수 있으므로 일괄 삭제하지 않는다.

- `GraphSeriesBuilder.KnownValues`의 0~30일 nullable 값을 재사용한다. 0% 기준 위/아래 막대·부호 있는 %·일자를 표시한다. 미열람은 잠금/공백, 알려진0은 0% 표식이다.
- 기존 무료/구매 출처 표시와 구매 버튼을 유지한다. 시장 전체 막대는 A의 `MARKET_REVEAL`을 받은 뒤에만 그린다.
- Y축은 `UiRules.AbsoluteChangeCapBps` 등 공개 설정, 툴팁은 현재 열람값만 사용한다. 막대 색만으로 증감/잠금 상태를 구분하지 않는다.
- 날짜0/30의 막대/클릭 영역이 양 끝에서 잘리지 않도록 동일 좌표 변환을 쓴다. `RectTransform`·Canvas 배율/카메라에 맞게 포인터 좌표를 변환하고, 화면 픽셀 좌표를 곧바로 날짜로 나누지 않는다.

통과 기준: **G01~G04**, 후속 I01의 날짜 좌표. 변경할 그래프가 시장 시세인지 플레이어 누적 추이인지 구분한다.

## NEXT-D02: 진입·청산 클릭 초안

현재 `InvestmentDraft`/`OrderInputValidator`/`RemoveInterval`을 재사용한다. 회사별 진행 중 진입일 후보와 완성 구간을 분리하고 첫 클릭 진입→둘째 클릭 청산→합법이면 `TryAddInterval`로 반영한다. 실패 시 완성 구간을 오염시키지 않고 안내한다.

우클릭/취소 버튼은 진행 중 후보를 해제한다. 완성 구간은 삭제 버튼으로 제거하고 다시 클릭할 수 있게 한다. 기업당 최대2개·5~10일·비중·겹침 검사는 기존 규칙과 같고 미열람 날짜도 클릭 가능하다. 전체 날짜 영역이 클릭을 받아야 하므로 현재 `LineChartGraphic.raycastTarget=false` 설정을 그대로 두고 클릭이 된다고 가정하지 않는다. 전용 입력 레이어 또는 별도 포인터 핸들러를 연결한다.

처음 클릭·취소·삭제는 로컬 초안만 바꾼다. 주문 확정 때만 명령을 보내고 pending/잠금/단계 변경 시 클릭을 비활성화한다. `UiKit.Clear` 후 재생성으로 후보가 사라지거나 첫 확정 클릭이 먹히지 않는 문제를 검사한다. 턴/본인 선택 기업이 바뀌면 후보/초안을 적절히 폐기하고 재접속 시 서버 확정 주문을 우선한다.

통과 기준: **I01~I05**, B가 같은 주문을 받아 서버 검증한다.

## NEXT-D03: 기업 표시명과 이미지

`InvestmentPage.BuildSelectionGrid`, `InfoPurchasePage`의 표시용 기업 카탈로그를 공통으로 사용한다. 회사명/그림과 기업 ID를 매핑하며 네트워크 ID는 바꾸지 않는다. 에셋이 없는 경우 텍스트/기본 아이콘으로 표시하고 선택을 막지 않는다. 실제 브랜드로 확정된 이미지가 없으므로 임시 표시임을 인계에 남긴다. 신규 에셋/폴더에는 `.meta`를 함께 포함한다.

통과 기준: **S01**. 화면 6기업이 일관된 이름·그림·변동성·열람수를 표시해야 한다.

## NEXT-D04: 자리 표시와 선택·취소 기본안

현재 버튼의 `() => _c.SelectCompany(id)`를 후보 선택으로 바꾸고, 후보 취소/교체와 별도 확정 버튼을 제공한다. 확정 한 번만 기존 명령을 보내며 후보는 정원을 예약하지 않는다. 확정 성공 후 취소 버튼은 제공하지 않는다. 이는 [계획의 권장안](../05_다음_구현_계획.md)이며 서버 확정 취소까지 구현한 것으로 보고하지 않는다.

내 차례 시작/종료, `selectionIndex` 변경, 마감/자동 선택, pending 중 버튼 상태를 분리한다. 서버가 차례를 넘기면 후보를 폐기한다. 로컬 후보가 있어도 `OwnSelections`나 `remainingSeats`를 낙관적으로 변경하지 않는다.

정원2칸은 다음 계산으로 표시한다.

```text
내 확정 수 = 본인 selectedCompanies에 기업이 있으면 1, 없으면 0
점유 총수 = 2 - 공개 remainingSeats
익명 선점 수 = 점유 총수 - 내 확정 수
빈칸 수 = remainingSeats
```

개인 결과/공개 상태가 잠깐 다른 순서로 도착하면 개수를 0~2로 제한하고 다음 권위 스냅샷에서 맞춘다. ‘선점됨’에 타인 이름/주문을 붙이지 않는다. 내 후보는 실제 칸 점유와 구분한 테두리 등으로 표시한다.

통과 기준: **S02~S04**. 인계: A/B에 후보 취소가 명령0회·원장무변경인 증거와 확정/마감 입력.

## NEXT-D05~07: 차주 전광판·기능 화면·레퍼런스 기반 UI

NEXT-D05는 기존 전광판을 재사용해1~10턴별 자산·턴/누적 성과·추이·순위 갱신과10턴 최종 결과를 표시한다. 입찰 결과·능력/아이템 공개 이벤트는 A가 허용한 필드만 사용하고 타인 구매값/주문은 드러내지 않는다. 과거 턴 조회는 현재 턴 진행/주문을 바꾸지 않는 읽기 모드로 만든다. 통과 기준: **N11**.

NEXT-D06은 능력 후보 선택/설명/기본선택, 상점/인벤토리/사용 대상·횟수/쿨다운, 3·6·9턴 입찰 입력/확정/대기/마감/결과 화면을 만든다. 비활성 사유·비용·실패 무변경·잠금을 명확히 표시하고 C/B 상태를 로컬에서 먼저 확정하지 않는다. 통과 기준: **N04~N10**.

NEXT-D07은 UI 레퍼런스를 토대로 화면 구성·색/글꼴·정보 위계·전환/강조·입찰 마감/시장 공개/순위 역전·최종 결과 연출을 구체화한다. 구체 레퍼런스 파일/URL은 아직 지정된 상태가 아니므로 구현 시 실제 출처와 화면별 적용 요소를 기록한다. 박진감 있는 연출 중에도 잔여시간·조작 가능 상태·날짜/금액이 읽혀야 하고, 서버 마감이나 개인 정보 경계를 바꾸지 않는다. 통과 기준: **N12**.

완료 보고에 주요 화면과 사용 레퍼런스 대응, 입찰/공개/결과 연출 영상 또는 실행 기록, 실제 해상도/마우스 검증을 남긴다. 위 작업은 차주 범위이며 막대/마우스 입력만으로 UI 구체화 전체를 완료했다고 표시하지 않는다.

### 공통 시간·BOT 설정 표시

INFO 시간은 A의 마감 DTO를 `PhaseClock`에 동기화해 **1:30**으로 보이게 한다. 90초 상수를 UI에서 별도로 진행시키지 않는다. 전원 완료 버튼은 기존 `COMPLETE_PHASE`를 사용한다. BOT 난이도는 A의 설정 API를 받은 뒤 대기실의 방장 조작으로 연결하고 게임 시작 후에는 고정한다. 통과 기준: **T01, B04, R03**.

```text
D 담당으로 NEXT-D01→D02→D03/D04 순서로 구현하라.
막대는 0일차 대비 일별 값, 미열람은 값 없음으로 유지하라.
마우스 날짜/취소는 InvestmentDraft만 바꾸고 주문 확정 때 기존 명령을 전송하라.
자리 선택은 로컬 후보/취소/확정 기본안으로 구현하고 서버 확정 취소와 구분하라.
실제 TCP 경로를 유지하고 담당 Case·기존 회귀·마우스/화면 검증 결과를 보고하라.
```
