# 게임 UI 멀티플레이 연결

## 단계 안내 만료·확대 정보 구매·게임 일시정지

- 안내 배너는 턴·단계가 바뀌면 표시 중인 문구와 대기열을 즉시 지운다. 기업 선택 차례가 다음 참가자로 넘어가도 이전 차례 알림을 지운다. 지나간 정보 구매·주문 확정·정산 알림을 나중 화면에 새로 쌓지 않는다.
- 확대 그래프 하단에서도 해당 기업의 **6개 정보 묶음**을 구매한다. 보유 코인·무료 정보 횟수, 열람·구매 완료·요청 중 상태를 표시하며 축소하지 않고 그래프가 갱신된다. 작은 카드와 동일한 구매 규칙을 사용한다.
- 방장은 게임 중 왼쪽 위 **일시정지**를 누른다. 모든 참가자에게 정지 화면을 표시하고 서버의 게임 시간·단계 마감·선택 마감·봇 행동을 멈춘다. 화면 중앙 또는 왼쪽 위 **게임 재개**로 남은 시간부터 계속한다. 정지 중 서버의 게임 명령도 거절하므로 다른 참가자의 입력으로 진행되지 않는다. 대기실·종료 후에는 정지 버튼을 사용할 수 없다.
- **방장 Unity Editor의 Pause(Ⅱ)**도 같은 서버 정지에 연결된다. 다시 Pause를 해제하면 멈춘 시간을 제외하고 이어서 진행한다. 게임 내 버튼으로 이미 정지했다면 에디터 Pause를 해제해도 게임은 계속 정지 상태다. 참가자 에디터만 Pause하면 방장 서버는 계속 진행하므로 전체 정지는 방장에게 요청해야 한다.
- Unity의 **Stop(■)**은 Play 모드와 방을 종료하는 버튼이다. 이어서 플레이하려면 게임 내 일시정지나 방장 에디터의 Pause를 사용한다.
- 호스트 제어는 `NetworkSession`의 로컬 서버 API로만 제공하며 원격 참가자용 정지 명령은 추가하지 않았다. 정지·재개는 모든 클라이언트의 `PublicState.paused`로 전달한다. 서버가 정지한 기간은 게임 경과 시간에서 제외하고, 재개 전에 정지 중 대기 입력을 처리하여 마감 시각이 틀어지지 않게 한다.
- 정지 전의 기업 선택 후보와 투자 초안을 유지한다. 재개 시 남아 있던 선택 제한 시간부터 진행한다.
- 검증: .NET AValidation **49개**, Unity 전체 EditMode **157/157**, 마지막 배너·후보 보존 수정을 반영한 실제 UI 재검사 **4/4** 통과. 실패·건너뜀 0. 실제 TCP 호스트·참가자의 정지 상태 동기화, 원격 정지 권한 차단, 정지 중 원시 명령 거절, 재개 시간 보정, 에디터 정지 콜백, 확대 구매·무료 정보·중복 요청 방지·구매 후 갱신, 지난 단계·차례·턴 배너 만료를 검증했다.
- 증거: `Logs/AValidation-results.json`, `Logs/PausePurchase-final-results.xml`, `Logs/PausePurchase-final-Unity.log`, `Logs/PausePurchase-ui-final-results.xml`, `Logs/PausePurchase-ui-final-Unity.log`. 화면 캡처: `Logs/PlanningScreens/game-paused.png`, `Logs/PlanningScreens/zoom-purchase.png` (Git 제외). GPU 렌더링을 확인했으며 검사 복사본과 작업 폴더의 수정 소스도 일치한다.

## 2026-11-06 정보 그래프 확대와 개인 투자 계획

1. 정보 구매 창의 기업 카드에서 **확대하기**를 누르면 해당 그래프가 태블릿 중앙에 크게 열린다. **축소하기**를 누르면 6개 기업으로 돌아간다. 확대 중에도 구매한 정보와 타이머는 갱신되며, 미열람 구간의 주가는 공개하지 않는다.
2. 확대 화면에서 **찜하기**와 **1~6순위**를 지정한다. 이미 사용한 순위를 지정하면 두 기업의 순위를 맞바꾼다. 찜과 순위는 본인에게만 보이는 메모이며 투자 자리 예약은 아니다.
3. 그래프에서 **진입일 → 청산일** 순서로 클릭하면 계획을 저장한다. 기존 주문 규칙대로 5~10일 보유, 기업별 최대 2구간, 구간 겹침 금지를 적용한다. 우클릭 또는 **진입 후보 취소**로 후보를 취소하고, **삭제**로 저장한 구간을 지운다. 미열람 날짜에도 계획할 수 있지만 주가와 수익률을 추정해서 표시하지 않는다.
4. 투자 자리 경쟁 화면에 찜·순위·계획 구간을 표시한다. 선택한 두 기업의 계획은 투자 주문 초안으로 복사되며, 투자 화면에서 수정한 뒤 **주문 확정**으로 제출한다.
5. 주문 확정 후와 전체 시장 공개 시 그래프에는 실제 확정된 본인 주문의 진입·청산을 표시한다. 투자 화면에서 수정했다면 이전 계획 대신 수정한 구간을 표시하며, 선택하지 않은 기업의 계획을 확정 주문처럼 표시하지 않는다.
6. 개인 메모는 같은 턴의 화면 전환 동안 유지되고 다음 턴에 초기화된다. 파일 저장이나 새 클라이언트로의 복원은 지원하지 않는다.

## 2026-11-06 D 화면 실제 게임 연결

- `DevTabletUI` 씬에서 Play 후 방을 만들거나 참가하면 상단에 **전광판 / 입찰 결과 / 내 능력 / 상점 / 보유 아이템 / BOT 난이도** 메뉴가 보인다. 위·아래 가장자리의 상점·인벤토리와 내 능력 카드도 같은 화면을 연다.
- 게임 시작 전 능력 선택은 D의 3후보 카드 → 능력 확정으로 실제 `SELECT_ABILITY`를 전송한다. 기본 시간 제한은 없으며 방장은 미선택자에게 첫 후보를 적용해 진행할 수 있다.
- 3·6·9턴 입찰은 D의 입찰 화면에서 금액·자리 선호·프리패스를 입력하고 실제 `SUBMIT_BID`를 전송한다. 요청 중 입력을 잠그고 서버 확인 후 확정한다. 입력 도중 타이머 갱신으로 화면을 다시 만들지 않는다.

- BOT 난이도는 대기실에서 방장만 변경할 수 있으며 기존·새 BOT 모두에게 적용된다. 게임 시작 후 고정된다.

- **상점 구매·일반 아이템 사용·전체 능력 효과는 서버의 후속 범위다.** 상점·인벤토리의 실행 버튼은 비활성화하고 사유를 표시한다. 예시 잔액·예시 지급·로컬 효과 계산은 실제 게임에 넣지 않았다.

## 실행

1. 모든 PC에서 같은 버전의 프로젝트로 `Assets/Scenes/DevTabletUI.unity`를 열고 Play한다. 이 씬을 기본 빌드 씬으로도 등록했다.
2. 방장은 이름과 포트(기본 `7777`)를 입력하고 **방 만들기**를 누른다. 방장 주소 입력 칸은 참가할 때만 사용한다.
3. 다른 PC는 대기실에 표시된 방장 PC의 IPv4 주소와 같은 포트를 입력하고 **참가**를 누른다. `127.0.0.1`은 같은 PC에서 테스트할 때만 쓴다. 주소가 여러 개면 참가자에게 도달 가능한 실제 연결의 주소를 사용한다.
4. 방장은 사람이 모두 입장한 뒤 **빈자리를 BOT으로 채우기**를 선택할 수 있다. 자동으로 4인까지 채우며 처음부터 BOT을 넣지는 않는다. **BOT 모두 내보내기**를 누르면 사람이 참가할 자리를 다시 확보한다.
5. 사람들은 **준비**를 누른다. BOT은 자동 준비한다. 4명이 모두 준비하면 방장이 **게임 시작**을 누른다.
6. 기존 정보 구매·기업 선택·투자 주문·시장 공개·정산 화면으로 이어진다. **방 나가기**로 접속 화면에 돌아갈 수 있다. 방장이 나가면 방은 종료되고 참가자 화면에는 종료 이유와 이미 받은 결과가 남는다.

## 동작과 현재 범위

- 서버는 모든 로컬 IPv4 인터페이스에서 수신한다. 화면 연결은 PC 방화벽이나 학교 Wi-Fi의 단말 간 통신 제한을 바꾸지 않는다. 기존에 허용한 참가자 외의 PC에는 별도 방화벽 허용이 필요할 수 있다. 빌드 실행 파일의 방화벽 규칙은 Unity Editor와 별개다.
- 방장만 원본 시장을 로드하고 실제 `MarketService`와 `SharedInformationService`를 생성한다. 참가 UI에는 개인에게 허용된 정보만 전송한다. 에디터는 기존 서버 fixture, 빌드는 기존 예제 시장 생성 경로를 사용한다. 서버 fixture를 Resources/StreamingAssets로 옮기지 않았다.
- BOT은 기존 `DevBot` 전략이다. 정보를 구매하지 않고, 가능한 기업을 선택해 60:40·10→15일/5→10일 주문을 제출한다. 결과는 사람과 동일하게 실제 B가 계산한다. 무작위 투자 AI를 새로 추가한 것은 아니다.
- BOT 등록·제거는 대기실에 한정한다. 게임 도중 사람을 BOT으로 교체하지 않는다. 연결이 끊긴 대기실 참가자의 자리는 방장이 채우기를 눌렀을 때 예약을 해제한다.
- 접속 실패·포트 중복·정원 초과는 접속 화면에서 안내한다. 연결 대기는 제한 시간이 있고 취소할 수 있다. 접속 화면에서 다시 참가하는 것은 새 입장이다. 기존 API의 토큰 재접속은 유지되지만 이 UI의 자동 재접속 기능은 아직 없다.
- 게임 진행은 기존 구현 범위인 한 턴이다. 과거 정보·정산 내역을 보관하는 상태 저장소 정책은 그대로 사용한다.
